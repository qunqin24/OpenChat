v1.1.7 的补丁版本：流式回答显示更匀速、新字淡入，以及两处修复。

*English summary below.*

## 改进

- **回答匀速逐字出现。** 以前文字按批到达后会尽快放完再等下一批，慢模型或每半秒才送一批的中转站读起来是「蹦出几个字→停一下」。现在按文字到达的速度匀速显示，手里留约 0.25 秒的字，下一批到之前不会放空。一次到一大段时约 1 秒逐字放完，不再像是直接冒出来；思考结束后的正文、界面块后面的文字这类新出现的段落，也从头逐字打出，不再整句直接出现。中途打开或刷新正在输出的长回答时，末尾一两行会重新打一遍。
- **新字淡入。** 正在输出的最后几个字上有一段很短的渐变，新字从淡到实地出现，中文同样有效。全程只多一个页面元素，长回答下 CPU 占用和不加时一样（不会重演 v1.1.0 逐字动画拖慢页面的问题）。

## 修复

- 弹窗打开时，通知条（例如「服务端已更新」的「刷新」）点不了，点了还会把弹窗关掉。
- 模型偶尔输出一个空的界面块时，会显示「这个界面无法显示」和一个空灰框；现在直接不显示。

## 升级

在部署目录（仓库根目录）运行：

```bash
docker compose -f deploy/docker-compose.yml --env-file deploy/.env pull openchat
docker compose -f deploy/docker-compose.yml --env-file deploy/.env up -d
```

`up -d` 会用新镜像重新创建容器；只 `restart` 跑的还是旧版本。如果在 `deploy/.env` 里用 `OPENCHAT_IMAGE` 固定了版本号，先改成 `ghcr.io/qunqin24/openchat:1.1.8`。用 1Panel 等面板升级容器时，镜像写 `:latest` 要勾选「强制拉取镜像」，或直接写 `:1.1.8`。没有新的数据库迁移。

## English summary

A patch release for v1.1.7.

- **Streamed answers at an even pace:** text is shown at the pace it arrives, about a quarter second behind, so a slow model or a relay that delivers every half second reads as steady typing instead of bursts and stops. A large batch is typed out over about a second, and a part that starts mid-stream (the answer after the reasoning, text after an interface block) is typed from its start instead of appearing whole. A page opened part-way through a long answer retypes its last line or two.
- **The newest characters fade in,** through a short gradient over the end of the last line - for Chinese too - with one element and no measurable CPU cost.
- **Fixed:** notifications (such as Reload on the update notice) could not be pressed while a dialog was open, and pressing closed the dialog; an empty interface block showed as "this interface cannot be shown" over an empty box and is now left out.

To upgrade, from the repository root:

```bash
docker compose -f deploy/docker-compose.yml --env-file deploy/.env pull openchat
docker compose -f deploy/docker-compose.yml --env-file deploy/.env up -d
```

`up -d` recreates the container from the new image; a plain `restart` keeps running the old one. If `deploy/.env` pins `OPENCHAT_IMAGE` to a version, change it to `ghcr.io/qunqin24/openchat:1.1.8` first. No new database migrations.
