v1.0.0 的补丁版本：修复内容审核的两处绕过和三处相关问题。建议所有 v1.0.0 部署升级。

*English summary below.*

## 安全修复

- **超长文本不再能绕过审核。** 「用指定模型审核」且「审核出错时放行」时，把一条会被拦下的消息补到很长，审核会因分片超限而按"出错"放行。现在超出可审核范围的消息（文字太长、一条消息超过 6 张图片等）一律直接拒绝，「出错时放行」只用于审核服务真正出错的时候。默认的 OpenAI Moderation 不受此问题影响。
- **游客的记忆编号不能再夹带文字。** 游客请求里的记忆编号会进入系统提示词却没有格式限制。现在严格校验，游客请求里其他会进入提示词的字段也一并收紧。游客模式默认关闭。

## 其他修复

- 模型修改游客的记忆之后，同一个对话继续发消息不再报「历史记录无效」。
- 被拦下的游客消息使用服务器时间排序，浏览器时钟不准时不再错位，改写它时也不会带上后面的消息。
- v1.0.0 的数据库迁移把「模型写下、后来被用户改过」的记忆误标成了已审核。新迁移撤销这些标记，这些记忆会在下一个新对话开始时重新审核。

## 新功能

- 后台 → 系统 → 常规 显示当前版本，并可以检查更新：有新版本时给出版本号和更新说明的链接。检查由服务器向 GitHub 发起，只在管理员打开这一页（最多每 6 小时一次）或点「检查更新」时进行。

## 升级

在部署目录（仓库根目录）运行：

```bash
docker compose -f deploy/docker-compose.yml --env-file deploy/.env pull openchat
docker compose -f deploy/docker-compose.yml --env-file deploy/.env up -d
```

`up -d` 会用新镜像重新创建容器；只 `restart` 跑的还是旧版本。如果在 `deploy/.env` 里用 `OPENCHAT_IMAGE` 固定了版本号，先改成 `ghcr.io/qunqin24/openchat:1.0.1`。数据库迁移在启动时自动执行。

## English summary

A patch release for v1.0.0 that closes two content-moderation bypasses and fixes three related issues. Every v1.0.0 deployment should upgrade.

- **Security:** an over-long message can no longer slip through model-mode moderation set to "allow on error" (a message too large to check - too long, or more than six images - is now refused outright); a guest's memory references are strictly validated so they can no longer carry text into the system prompt, along with the other guest fields that reach it.
- **New:** Admin → System → General shows the running version and checks GitHub for a newer release (only when an administrator opens the page, at most every six hours, or presses the button).
- **Fixes:** a guest conversation keeps working after the model edits a memory; a guest's refused message is ordered by server time, so a skewed browser clock no longer misplaces it; memories written by the model and later edited by the user are no longer treated as already checked (a new migration clears those marks).

To upgrade, from the repository root:

```bash
docker compose -f deploy/docker-compose.yml --env-file deploy/.env pull openchat
docker compose -f deploy/docker-compose.yml --env-file deploy/.env up -d
```

`up -d` recreates the container from the new image; a plain `restart` keeps running the old one. If `deploy/.env` pins `OPENCHAT_IMAGE` to a version, change it to `ghcr.io/qunqin24/openchat:1.0.1` first.
