v1.1.5 的补丁版本：记忆的几处界面改进。

*English summary below.*

## 改进

- **编辑记忆用单独的弹窗。** 点一条记忆（或它的编辑按钮）、点「添加记忆」，都会打开一个弹窗：多行文本框能看到整条内容，旁边显示字数，「取消」「保存」，⌘/Ctrl + Enter 也能保存。保存失败时错误显示在文本框下面，写的内容不会丢；Esc 只关这个弹窗。原来列表里一行的输入框去掉了。
- **回复里的「已更新记忆」只占一行。** 记忆最长 200 字，以前会把提示撑成好几行；现在放不下时用省略号截断，点文字展开全文，再点收起。
- **「最近由模型更改」默认折起。** 记忆管理里这一块只显示标题和条数，点开才列出，每条最多两行，记忆列表不再被挤到下面。

## 升级

在部署目录（仓库根目录）运行：

```bash
docker compose -f deploy/docker-compose.yml --env-file deploy/.env pull openchat
docker compose -f deploy/docker-compose.yml --env-file deploy/.env up -d
```

`up -d` 会用新镜像重新创建容器；只 `restart` 跑的还是旧版本。如果在 `deploy/.env` 里用 `OPENCHAT_IMAGE` 固定了版本号，先改成 `ghcr.io/qunqin24/openchat:1.1.6`。用 1Panel 等面板升级容器时，镜像写 `:latest` 要勾选「强制拉取镜像」，或直接写 `:1.1.6`。没有新的数据库迁移。

## English summary

A patch release for v1.1.5 with a few memory interface improvements.

- **A memory is added and edited in a dialog of its own:** a box several lines tall with the count, Cancel and Save (Cmd/Ctrl+Enter); an error shows under the box and keeps what was written; Escape closes only the dialog. The inline one-line fields in the list are gone.
- **The "memory updated" note in a reply is one line,** cut with an ellipsis and opened by a click (a memory may be 200 characters).
- **"Recently changed by the model" is folded by default** in the memory manager, opened from its title, each change at most two lines.

To upgrade, from the repository root:

```bash
docker compose -f deploy/docker-compose.yml --env-file deploy/.env pull openchat
docker compose -f deploy/docker-compose.yml --env-file deploy/.env up -d
```

`up -d` recreates the container from the new image; a plain `restart` keeps running the old one. If `deploy/.env` pins `OPENCHAT_IMAGE` to a version, change it to `ghcr.io/qunqin24/openchat:1.1.6` first. No new database migrations.
