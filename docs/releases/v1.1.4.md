v1.1.3 的补丁版本：手机端禁止缩放并适配刘海屏，上下文压缩改为只能自动进行，以及升级后版本号显示不对的问题。

*English summary below.*

## 改进

- **手机端适配。** 页面不能再双指缩放或双击放大，iPhone 上点输入框也不会自动放大；Android 弹出键盘时输入框留在键盘上方。页面顶部、左右和侧栏底部让开刘海、圆角和底部横条，添加到主屏幕或横屏时不会被挡住；点按钮时不再闪一下灰色。
- **上下文压缩只能自动进行。** 去掉了圆环菜单里的「立即压缩」和「上下文过长」时的「压缩上下文」按钮。改为：模型因上下文过长拒绝请求时，开着自动压缩的回答会自动压缩一次并立刻重试；仍然超长时才报错，提示新建对话或换一个上下文更大的模型。「撤销压缩」保留。
- **压缩后圆环立即更新。** 以前压缩完圆环还显示压缩前的用量，要等下一次发消息才变；现在立即显示压缩后的估算值并注明是估算，下一次回答后换成实际用量。

## 修复

- **iPhone 上长对话的消息偶尔变空白。** Safari 内核在「屏幕外的消息跳过渲染」上有绘制 bug，Open WebUI 同样因此在 Safari 内核上关闭了它；现在 Safari 和 iPhone 上的所有浏览器都不再使用，其他浏览器不变。
- **升级后「关于」里的版本号还是旧的。** 版本号以前读容器的 `APP_VERSION` 环境变量，用 1Panel 等面板升级时这个变量会沿用旧容器的值。现在版本号编译进程序本身，`APP_VERSION` 环境变量不再有任何作用，面板里留着的可以删掉。

## 不兼容的变更

- 删除了手动压缩的接口 `POST /api/v1/conversations/{id}/compaction` 和 `POST /api/v1/guest/compaction`。读取压缩状态（`GET`）和撤销（`DELETE`）不变。只影响自己调用这两个接口的脚本。

## 升级

在部署目录（仓库根目录）运行：

```bash
docker compose -f deploy/docker-compose.yml --env-file deploy/.env pull openchat
docker compose -f deploy/docker-compose.yml --env-file deploy/.env up -d
```

`up -d` 会用新镜像重新创建容器；只 `restart` 跑的还是旧版本。如果在 `deploy/.env` 里用 `OPENCHAT_IMAGE` 固定了版本号，先改成 `ghcr.io/qunqin24/openchat:1.1.4`。用 1Panel 等面板升级容器时，镜像写 `:latest` 要勾选「强制拉取镜像」，或直接写 `:1.1.4`。没有新的数据库迁移。

## English summary

A patch release for v1.1.3.

- **Mobile:** no pinch or double-tap zoom, and iOS no longer zooms into a field when it is focused; on Android the composer stays above the keyboard. The page keeps clear of the notch, rounded corners and home indicator (also as a home-screen app or in landscape), and taps no longer flash grey.
- **Context compression is automatic only:** the "Compress now" item and the "Compress context" button are gone. When the model refuses a request as too long, a run with automatic compression on compresses once and retries straight away; only if it is still too long does it fail, suggesting a new conversation or a model with a larger context. Undoing a compression stays.
- **The context meter updates after a compression,** showing an estimate (marked as such) until the next request reports real figures.
- **Fixed:** messages in a long conversation could go blank on iPhone. WebKit's content-visibility has a paint bug, and as in Open WebUI it is no longer used there (Safari and every iOS browser); other browsers are unchanged.
- **Fixed:** "About" showed the old version after an upgrade, because it read the container's `APP_VERSION`, which panels such as 1Panel carry over from the old container. The version is now built into the binary; `APP_VERSION` has no effect any more and can be removed.
- **Breaking:** the manual compression endpoints `POST /api/v1/conversations/{id}/compaction` and `POST /api/v1/guest/compaction` are removed (`GET` and `DELETE` stay). Only scripts calling them are affected.

To upgrade, from the repository root:

```bash
docker compose -f deploy/docker-compose.yml --env-file deploy/.env pull openchat
docker compose -f deploy/docker-compose.yml --env-file deploy/.env up -d
```

`up -d` recreates the container from the new image; a plain `restart` keeps running the old one. If `deploy/.env` pins `OPENCHAT_IMAGE` to a version, change it to `ghcr.io/qunqin24/openchat:1.1.4` first. No new database migrations.
