这一版新增 **Notion、麦当劳、瑞幸咖啡三个内置插件**和 **Command Code 渠道**，插件支持**每个人填自己的令牌**，并加强了插件凭证的保护。

*English summary below.*

## 新功能

- **Notion 插件。** 接 Notion 官方的 MCP 服务：搜索和阅读页面与数据库，写文档、改数据库、读写评论。每个人用自己的 Notion 账号授权，只能访问这个账号本来就能访问的内容。不用另外注册 OAuth 应用，管理员在后台打开即可。
- **麦当劳插件。** 接麦当劳中国官方的 MCP 服务，只在中国大陆可用：找门店、看菜单和价格、点麦乐送或到店取餐、领优惠券、查积分和订单。下单前会先算价格并请你确认，下单后给出支付链接，由你自己付款。
- **瑞幸咖啡插件。** 接瑞幸官方的 MCP 服务：找附近门店、选饮品和规格、看优惠后的价格、下自提订单、查询和取消订单。同样先确认再下单，付款二维码由你自己扫码支付。
- **每人填自己的令牌。** 麦当劳和瑞幸不走 OAuth 授权，而是给每个人发一个绑定自己账号的令牌。安装这类插件时，在弹窗里粘贴自己的令牌，旁边有「去获取」链接。令牌会先拿去服务那边试一次，通过才保存，并且加密存储。服务不再接受时，插件页会提示换一个新的。管理员在后台也可以给自己添加的插件选这种认证方式。
- **Command Code 渠道。** 渠道预设里新增 Command Code（Provider API）。Claude、GPT 和开源模型用同一个地址和 key，每个模型自动走它支持的接口。

## 改进

- 插件图标可以设置「图形颜色」，品牌色不是黑或白时（比如麦当劳红底黄拱门）也能画对。
- 用量日志里，`z-ai/glm-5.3-flash` 这类带厂商前缀的模型名现在也显示对应的模型图标。
- Command Code 不接受 PDF 文件内容块。一个模型只要有 Command Code 渠道在服务，它收到的 PDF 就改为发送提取出的文字。

## 安全

- 插件服务重定向到别的主机时不再跟随，凭证只会发给它所属的服务。这也影响此前的 OAuth 插件和「统一请求头」插件。
- 每个人的令牌绑定在插件当时的地址和认证方式上。管理员改了地址或认证方式后，旧令牌不会发给新服务，插件页会提示重新连接。
- 插件服务的报错里如果带着令牌，写日志和告诉模型之前会先抹掉。
- 服务对某次调用回 403（比如令牌缺少某项权限）时，只结束这一次调用，不会把整个连接标成失效。
- 两个人同时第一次连接 Notion 这类自动注册的插件时，不会再有一人授权失败。
- 浏览器的本地缓存不再保存还没发出的请求，断网时粘贴的令牌不会留在浏览器存储里。

## 升级

这一版有数据库迁移，启动时自动执行，部署文件没有变化。在仓库根目录运行：

```bash
docker compose -f deploy/docker-compose.yml --env-file deploy/.env pull openchat
docker compose -f deploy/docker-compose.yml --env-file deploy/.env up -d
```

如果在 `deploy/.env` 里用 `OPENCHAT_IMAGE` 固定了版本号，先改成 `ghcr.io/qunqin24/openchat:1.6.0`。

新的内置插件默认关闭，管理员在后台「插件」页打开后，用户才能在侧栏「插件」页安装。

## English summary

This release adds **Notion, McDonald's China and Luckin Coffee as built-in plugins** and a **Command Code channel**. Plugins can now take **each person's own token**, and plugin credentials are better protected.

- **Notion:** Notion's hosted MCP server: search and read pages and databases, write, update databases, comment. Each person signs in with their own account; no OAuth app to register.
- **McDonald's China and Luckin Coffee:** ordering through their official MCP servers (mainland China only). Stores, menus and prices come from the service; orders are previewed and confirmed first, and you pay yourself through the link or QR code they return.
- **Personal tokens:** a plugin can take a token each person gets from the service for their own account. It is tried on the service before it is kept, stored encrypted, and the plugins page asks for a new one when the service stops accepting it.
- **Command Code channel:** a preset for its Provider API, with each model sent to the API that serves it. Because it accepts text and images only, a model it may serve gets a PDF's extracted text instead of the file.
- Plugin icons can set a glyph colour; the usage log draws `maker/model` ids with their family's icon.
- **Security:** plugin requests follow redirects only within the same origin; a person's token is bound to the plugin's address and sign-in method, so changing either never sends it elsewhere; credentials are scrubbed from service errors; a 403 ends one call instead of disabling the connection; concurrent first sign-ins with dynamically registered clients both work; the browser cache no longer stores unsent requests.

There are database migrations, run at start; the deploy files did not change. To upgrade, from the repository root:

```bash
docker compose -f deploy/docker-compose.yml --env-file deploy/.env pull openchat
docker compose -f deploy/docker-compose.yml --env-file deploy/.env up -d
```

If `deploy/.env` pins `OPENCHAT_IMAGE`, change it to `ghcr.io/qunqin24/openchat:1.6.0` first. The new built-in plugins start switched off; an administrator turns them on on the Plugins page.
