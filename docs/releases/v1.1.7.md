v1.1.6 的补丁版本：修复发送带图片的消息后，图片在回答期间消失的问题。

*English summary below.*

## 修复

- **发出的图片在回答期间不显示。** 发送带图片的消息后，图片有时会立刻消失，直到回答结束才重新出现。原因是服务器推送的「回答开始」事件比发送请求的响应先到时，页面用了推送里那份不带图片的消息，响应到了也没补上。现在会把响应里的图片补回去。同一个对话在另一个标签页或设备上开着时，那边回答期间仍看不到图片，回答结束后正常显示。

## 升级

在部署目录（仓库根目录）运行：

```bash
docker compose -f deploy/docker-compose.yml --env-file deploy/.env pull openchat
docker compose -f deploy/docker-compose.yml --env-file deploy/.env up -d
```

`up -d` 会用新镜像重新创建容器；只 `restart` 跑的还是旧版本。如果在 `deploy/.env` 里用 `OPENCHAT_IMAGE` 固定了版本号，先改成 `ghcr.io/qunqin24/openchat:1.1.7`。用 1Panel 等面板升级容器时，镜像写 `:latest` 要勾选「强制拉取镜像」，或直接写 `:1.1.7`。没有新的数据库迁移。

## English summary

A patch release for v1.1.6.

- **Fixed:** images in a sent message could vanish until its answer ended. When the events stream announced the run before the send's response arrived, the page kept the event's copy of the question, which carries no attachments; the response's are now put back on it. Another tab or device following the same conversation still shows the images only once the answer has ended.

To upgrade, from the repository root:

```bash
docker compose -f deploy/docker-compose.yml --env-file deploy/.env pull openchat
docker compose -f deploy/docker-compose.yml --env-file deploy/.env up -d
```

`up -d` recreates the container from the new image; a plain `restart` keeps running the old one. If `deploy/.env` pins `OPENCHAT_IMAGE` to a version, change it to `ghcr.io/qunqin24/openchat:1.1.7` first. No new database migrations.
