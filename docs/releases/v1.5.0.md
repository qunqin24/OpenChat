这一版加入**技能、深度研究、插件、图片生成和浏览器工具**，流式输出更顺，并修了几处安全问题。新功能默认都是关着的，或者只给管理员，管理员在后台打开后才会用到。

*English summary below.*

## 新功能

- **技能。** 技能就是模型在需要时打开来看的做事方法，用 Agent Skills 格式：一个 `SKILL.md` 加它引用的文本文件。
  - 有站点技能（管理员写）和个人技能（在「设置」里写）两种。可以导入 `SKILL.md`、`.zip`、`.skill`，也可以导出为 ZIP。
  - 每次保存都是一个新版本，保留最近 20 个。改了技能只影响新对话。
  - 在输入框打 `/` 可以给这条消息指定技能。
  - 个人技能和自定义指令一样要过内容审核。
  - 内置几个技能，管理员只能关掉，不能修改。
- **深度研究。** 在「+」里选「深度研究」。
  - 模型先给出研究计划，你可以修改、让它重拟，或者确认开始。
  - 开始后它派出几个研究员并行搜索、读一手来源，边研究边把分节报告写进写作块，每节附来源。
  - 每人每月有次数限制，默认 10 次，管理员不限，在后台可以改。
- **插件。** 插件由技能和远程 MCP 服务（Streamable HTTP）组成。管理员在后台添加，每个人在侧栏的「插件」页自己安装。
  - 需要个人账号的插件走 OAuth 2.1 + PKCE 授权，支持自动发现和动态注册。
  - 模型调用插件的方式是写一段受限的脚本（CodeMode）：没有网络、定时器和模块，运行时长、调用次数、输出大小和内存都有上限。
  - 工具分三档权限：始终允许、需要确认、禁止。需要确认的调用会在回答里停下来等你点允许。
  - 后台「插件调用」页记录谁调了哪个工具、结果如何，不记录参数和返回内容。
  - 内置以下插件，默认关闭，管理员开启后可用：GitHub，以及在进程内运行、不需要账号的 arXiv、OpenAlex、天气（Open-Meteo）、维基百科、Hacker News。
- **图片生成。** 管理员在「后台 → 图片生成」选一个图片模型并打开开关后，所有对话里的模型都可以自己决定出图或改图。
  - 支持 gpt-image、dall-e-3、Gemini、Seedream、Grok 等，尺寸、比例和质量会按各家的规则换算。
  - 生成的图片算作这个人的附件，占用存储配额。
  - 出图的提示词要过内容审核，被拒不计入违规。
  - 张数有三道上限：每次调用、每个回答、每人每天。每人每天默认 0，即不限，可以给单个用户另设配额。图片模型可以设置按张计费。
  - 回答里直接显示图片。把鼠标移到图片上可以下载，或点「拿来改」把它放进输入框接着改。
- **浏览器工具（第一期只给管理员）。** 模型可以操作一个 headless Chromium 打开网页、点击、填表，在「+」里打开。
  - 浏览器的所有流量都经 OpenChat 的代理，只能访问公网的 80 和 443 端口。
  - 提交表单、付款这类会改动东西的操作先问你。模型永远不会在密码框里输入，也不会下载或上传文件。
  - 部署时要另外加上 `deploy/docker-compose.browser.yml`（见下方「升级」），再在「后台 → 浏览器」打开。
- **网页读取可以改用 Jina Reader。** 在后台「联网搜索」页可以选三种方式：只用内置读取、内置读取被网站拒绝时改用 Jina、只用 Jina。
- **OpenAI 的 `chat-latest` 有了完整的模型信息**，包括上下文长度、价格和思考档位（只有 medium），使用日志里也显示 OpenAI 的图标。

## 改进

- **生成很快的回答连续流出，不再一段一段地跳出来。** 服务端每 50 毫秒推送一次新内容，页面在两次推送之间从上到下扫入，每段淡入 0.2 秒。
- 带引用的回复显示为引用块。
- App：新增启动画面；新对话页显示 Logo；模型选择器移到顶栏；输入框旁边显示上下文用量。
- 插件步骤的调用按参数逐个展开，显示每次调用的请求和返回。

## 修复

- **插件 OAuth 不能再被引去访问内网。** 插件服务给出的授权服务器地址、重定向，以及令牌请求，现在每一跳都要检查，只能连公网地址。管理员填写的服务地址本身仍然可以在内网。
- **渠道密钥不会再从流内错误进入日志。** 部分网关会在错误信息里回显 API Key，以前 Chat Completions、Anthropic 和 Gemini 流内的错误没有脱敏。
- **多个工具同时刷新插件令牌时，不会再把正常的连接标成需要重新授权。** 同一人同一插件的刷新现在排队进行，网络失败也不再算作授权失效。
- **断线时对话空闲，重连后会补上断线期间别处写下的回复。**
- 模型目录：`gpt-image-1.5`、Gemini 的 `*-image` 等图片模型不再被当成聊天模型列出。

## 升级

这一版有数据库迁移，启动时自动执行。部署文件也有改动，先更新仓库再拉镜像，在仓库根目录运行：

```bash
git pull
docker compose -f deploy/docker-compose.yml --env-file deploy/.env pull openchat
docker compose -f deploy/docker-compose.yml --env-file deploy/.env up -d
```

如果在 `deploy/.env` 里用 `OPENCHAT_IMAGE` 固定了版本号，先改成 `ghcr.io/qunqin24/openchat:1.5.0`。

- **插件凭证的加密密钥**会在第一次启动时生成在数据卷里，路径是 `data/secret.key`。这个数据卷要和数据库一起备份，丢了密钥，已保存的插件凭证就打不开了。如果想自己提供密钥，在 `deploy/.env` 里设置 `OPENCHAT_SECRET_KEY`，可以用 `openssl rand -base64 32` 生成。
- **要用浏览器工具**，启动时加上它的 compose 文件：

  ```bash
  docker compose -f deploy/docker-compose.yml -f deploy/docker-compose.browser.yml --env-file deploy/.env up -d
  ```

## English summary

This release adds **skills, deep research, plugins, image generation and a browser tool**, streams fast answers smoothly, and fixes several security issues. New features are off or admin-only until an administrator turns them on.

- **Skills:** instructions in the Agent Skills format (`SKILL.md` plus text files) that the model opens when a task calls for them: the site's (written by administrators) and each person's own (in Settings). Every save is a version (the latest 20 are kept), and an edit reaches new conversations only. Pick skills for a message with `/`. Skills import from `SKILL.md`, `.zip` or `.skill` and export as ZIP. A person's skills are moderated like custom instructions.
- **Deep research ("+" → 深度研究):** the model proposes a plan that you edit, have redrafted or start. Researchers then search in parallel and read primary sources, and a sectioned report is written into a document with sources. Each person gets 10 a month by default; administrators are unlimited.
- **Plugins:** skills plus a remote MCP service (Streamable HTTP), added by administrators and installed by each person. Per-person OAuth 2.1 with PKCE, discovery and dynamic registration. The model calls tools through bounded scripts (CodeMode). Tools are always allowed, need confirmation, or are blocked. A Plugin calls page records who called what, never the input or result. Built in, off by default: GitHub, plus in-process arXiv, OpenAlex, weather (Open-Meteo), Wikipedia and Hacker News.
- **Image generation (后台 → 图片生成):** the chat model makes and edits pictures with the image model the administrator picked. Supported models include gpt-image, dall-e-3, Gemini, Seedream and Grok. Pictures count as the person's attachments, and prompts are moderated. Limits apply per call, per answer and per person per day (default 0 = unlimited, with per-user allowances), and pricing per picture is optional. Pictures show in the reply, with download and "edit this" on hover.
- **Browser tool (administrators only for now):** a headless Chromium the model drives, opened from "+". All traffic goes through OpenChat's proxy to public addresses on ports 80 and 443 only. Consequential actions ask first; the model never types passwords and never downloads or uploads files. It needs `deploy/docker-compose.browser.yml` and 后台 → 浏览器.
- **Reading pages through Jina Reader:** choose the built-in reader, the built-in reader with Jina as a fallback, or Jina alone.
- **OpenAI's `chat-latest` gets full catalogue data:** limits, prices and thinking (medium only).
- **Fast answers stream as a flow:** batches every 50 ms, swept in and faded over 0.2 s.
- **App:** launch screen, logo greeting, model picker in the top bar, context meter.
- **Fixes:**
  - Plugin OAuth can no longer be steered to internal addresses.
  - Channel keys are scrubbed from in-stream errors in every adapter.
  - Concurrent plugin token refreshes no longer mark a good connection for reconnecting.
  - Reconnecting while idle fetches replies written elsewhere meanwhile.
  - Image models are no longer listed as chat models.

To upgrade, from the repository root (the deploy files changed, and there are database migrations, run at start):

```bash
git pull
docker compose -f deploy/docker-compose.yml --env-file deploy/.env pull openchat
docker compose -f deploy/docker-compose.yml --env-file deploy/.env up -d
```

If `deploy/.env` pins `OPENCHAT_IMAGE`, change it to `ghcr.io/qunqin24/openchat:1.5.0` first. The key that seals plugin credentials is created on first start as `data/secret.key` on the data volume. Back that volume up with the database, or set `OPENCHAT_SECRET_KEY` yourself. For the browser tool, add `-f deploy/docker-compose.browser.yml` to the `up` command.
