v1.1.9 的补丁版本：一个模型多个渠道时按优先级和权重调度、失败自动换渠道，模型目录定时更新，以及渠道的几处改进。

*English summary below.*

## 改进

- **渠道优先级与权重。** 渠道新增「优先级」（数字大的先用，默认 0）和「权重」（1~1000，默认 1），在渠道编辑面板的「调度」一栏设置，渠道列表显示优先级。同一个模型由多个渠道提供时，每次回答从优先级最高的渠道里按权重选一个，例如权重 3 和 1 约为 3:1。以前只会用最早添加的那个渠道。
- **失败自动换渠道。** 一次请求失败、而模型还没输出任何内容时，立即换到这个模型的下一个渠道重发，无需等待；回答进行中原渠道被停用或删除时也会换。上下文过长、或已经输出了部分内容时不换，照旧处理。
- **模型目录定时更新。** 以前 models.dev 的模型信息只在服务启动时（且超过一天）才更新，服务一直不重启就一直不更新。现在运行期间每小时检查一次，超过一天自动更新。模型市场标题旁恢复了「刷新目录」按钮和更新时间，失败时显示原因。
- **渠道名称不能重复**（不区分大小写）。升级时已有的重名渠道会保留最早的一个，其余自动改名为「名称 (2)」「名称 (3)」。
- **接口地址自动补全。** 只填域名（或域名加一个结尾 `/`）时，自动补上该类型的默认路径，例如 `/v1`；以前会请求到不存在的地址而失败。填了路径的照原样使用。

## 升级

在部署目录（仓库根目录）运行：

```bash
docker compose -f deploy/docker-compose.yml --env-file deploy/.env pull openchat
docker compose -f deploy/docker-compose.yml --env-file deploy/.env up -d
```

`up -d` 会用新镜像重新创建容器；只 `restart` 跑的还是旧版本。如果在 `deploy/.env` 里用 `OPENCHAT_IMAGE` 固定了版本号，先改成 `ghcr.io/qunqin24/openchat:1.1.10`。用 1Panel 等面板升级容器时，镜像写 `:latest` 要勾选「强制拉取镜像」，或直接写 `:1.1.10`。

**有一个数据库迁移**，启动时自动执行：渠道增加优先级和权重、去掉原来的排序字段（已有顺序换算为优先级保留），并给渠道名称加唯一约束（重名的按上面说的改名）。接口里渠道的 `sortOrder` 字段改为 `priority` 和 `weight`，只影响自己调用渠道接口的脚本。

## English summary

A patch release for v1.1.9.

- **Channel priority and weight:** when several channels offer a model, a run goes to the highest priority (higher first, default 0), and among equal priorities by weight (1–1000, default 1; 3 and 1 split about 3:1). Set in the channel panel's new Routing section. Previously the oldest channel always won.
- **Failover:** a request that fails before the model has written anything is made again at once on the model's next channel; a channel switched off or deleted mid-run is failed over from too. A context too long, or a partly written answer, stays where it is.
- **The models.dev catalogue refreshes on its own:** checked hourly and refreshed once a day old (it used to refresh only at boot). The marketplace's refresh button and last-updated time are back beside its title, with the reason when a refresh fails.
- **Channel names are unique** (ignoring case); existing clashes are renamed "Name (2)", "Name (3)" on upgrade, the oldest keeping its name.
- **A base URL that is only a host gets the type's default path** (such as `/v1`) instead of failing; a URL with a path is used as given.

To upgrade, from the repository root:

```bash
docker compose -f deploy/docker-compose.yml --env-file deploy/.env pull openchat
docker compose -f deploy/docker-compose.yml --env-file deploy/.env up -d
```

`up -d` recreates the container from the new image; a plain `restart` keeps running the old one. If `deploy/.env` pins `OPENCHAT_IMAGE` to a version, change it to `ghcr.io/qunqin24/openchat:1.1.10` first. **One database migration**, applied at startup: channels gain priority and weight in place of the sort order (existing order kept), and channel names become unique. In the API, a channel's `sortOrder` is replaced by `priority` and `weight`; only scripts calling the channel endpoints are affected.
