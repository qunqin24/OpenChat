OpenChat 的第一个正式版本：一个可以自己部署的 AI 聊天网站。接入你自己的模型渠道，一个二进制、一个 Docker 镜像就能上线。

*English summary below.*

## 亮点

- **多渠道、多模型**：二十多种渠道类型（Anthropic、OpenAI、Gemini、DeepSeek、阿里云百炼、火山方舟、OpenRouter 等，以及任意 OpenAI 兼容地址）；模型市场按 models.dev 的元数据管理能力、上下文和价格。
- **完整的对话体验**：流式回答、思考过程与强度、联网搜索与网页读取、生成式界面、向用户提问、图片与 PDF 附件、改写提问与重新生成、搜索对话、临时对话。
- **自动压缩上下文**：对话接近上下文窗口时由对话自己的模型概括较早的历史，原消息照常显示、可撤销；也能手动压缩。
- **个性化与隐私**：自定义指令和个人记忆，管理员看不到任何人的记忆；导出或删除自己的全部数据。
- **游客模式**（默认关闭）：不需要账号，对话只存在游客自己的浏览器里，按 IP 和总量限额。
- **注册控制**：关闭、开放、审批三种模式；待审批和被停用的账号登录时看到全屏提示和要联系的管理员。
- **花费控制**：按模型设置花费上限（总计 / 每月 / 每天），被停止或服务商没报用量的请求按估算计费；每个账号、每个游客地址同时进行的回答数有上限。
- **内容审核**：发送前审核用户输入（OpenAI Moderation 或指定模型），记录日志，多次违规自动停用账号或封禁游客地址；发往上游的请求带上不可逆的用户标识。
- **管理后台**：仪表盘、使用日志、渠道（含每个渠道的累计花费）、模型、用户、文件存储（本地或 S3 兼容，在线切换）、数据保留、系统设置。
- **便于排查**：JSON 日志可同时写入数据卷上的文件并按大小轮转；每个请求带 `X-Request-Id`，失败提示里显示编号，用户反馈时报这个编号即可。

## 部署

```bash
docker pull ghcr.io/qunqin24/openchat:1.0.0
```

镜像支持 `linux/amd64` 和 `linux/arm64`。用 `deploy/docker-compose.yml`（Postgres 18 + OpenChat + Caddy 自动 HTTPS）部署，步骤见 [部署指南](https://github.com/qunqin24/OpenChat/blob/v1.0.0/docs/deployment.md)。数据库迁移在启动时自动执行。

**注意**：登录限流、游客限额和游客封禁都按来访 IP 计算，必须部署在会正确设置转发头的反向代理后面。自带的 Caddyfile 已经配好，自己维护代理时参照 [反向代理说明](https://github.com/qunqin24/OpenChat/blob/v1.0.0/docs/deploy-caddy.md)。

## English summary

The first stable release of OpenChat, a self-hosted AI chat site: connect your own model providers and run it as one binary or one Docker image.

- **Providers and models**: 20+ provider types plus any OpenAI-compatible endpoint; a model catalogue with capabilities, context and prices from models.dev.
- **Chat**: streaming, reasoning with selectable effort, web search and page reading, generative UI, ask-the-user questions, image and PDF attachments, edit and regenerate, search, temporary chats, and automatic context compaction (undoable, also manual).
- **Personalisation and privacy**: custom instructions and memories that administrators cannot read; export or delete all of your data.
- **Guest mode** (off by default): no account, conversations kept only in the guest's browser, limited per address and in total.
- **Sign-up control**: closed, open or approval; pending and disabled accounts see a full-window notice with the administrator to contact.
- **Spend control**: per-model spending caps (total, monthly, daily), estimated cost for stopped requests or providers that report no usage, and a limit on answers running at once per account and per guest address.
- **Content moderation**: user input checked before it reaches the upstream (OpenAI Moderation or a chosen model), a moderation log, and automatic sanctions (accounts disabled, guest addresses banned); upstream requests carry a non-reversible end-user identifier.
- **Admin**: dashboard, usage logs, providers with their spend, models, users, file storage (local or S3-compatible, switchable live), retention and system settings.
- **Operations**: JSON logs optionally mirrored to a rotating file on the data volume; every response carries `X-Request-Id`, shown in error messages for support.

```bash
docker pull ghcr.io/qunqin24/openchat:1.0.0
```

Images for `linux/amd64` and `linux/arm64`. Deploy with `deploy/docker-compose.yml` (Postgres 18, OpenChat, Caddy with automatic HTTPS); see the [deployment guide](https://github.com/qunqin24/OpenChat/blob/v1.0.0/docs/deployment.en.md). Rate limits, guest limits and guest bans are per client address, so OpenChat must sit behind a reverse proxy that sets the forwarding headers correctly; the bundled Caddyfile does.
