v1.1.1 的补丁版本：修复每次发送新消息时画面跳到上一条回答、再跳回来的问题。

*English summary below.*

## 修复

- **发送新消息时画面不再闪跳。** 为了让长对话不卡，屏幕外的较早消息会跳过渲染，只有最新的一问一答始终完整绘制。发送新消息的那一刻，原来最新的一问一答第一次被套上这个优化，而浏览器还没记下它们的真实高度，就按占位高度排了一帧：对话一下变矮，滚动位置被拉到上一条回答，再跳回来。现在所有消息一直记着自己的真实高度，发送时画面稳定贴在底部。

## 升级

在部署目录（仓库根目录）运行：

```bash
docker compose -f deploy/docker-compose.yml --env-file deploy/.env pull openchat
docker compose -f deploy/docker-compose.yml --env-file deploy/.env up -d
```

`up -d` 会用新镜像重新创建容器；只 `restart` 跑的还是旧版本。如果在 `deploy/.env` 里用 `OPENCHAT_IMAGE` 固定了版本号，先改成 `ghcr.io/qunqin24/openchat:1.1.2`。用 1Panel 等面板升级容器时，镜像写 `:latest` 要勾选「强制拉取镜像」，或直接写 `:1.1.2`。没有新的数据库迁移。

## English summary

A patch release for v1.1.1.

- **Fixed:** every send made the page jump up to the previous answer and back. The newest exchange is always drawn while older messages skip rendering off-screen; the moment a message was sent below it, it was laid out once at a placeholder height because the browser had not recorded its real one, shrinking the transcript and pulling the scroll position up. Every message now keeps its real height recorded, so the page stays at the bottom.

To upgrade, from the repository root:

```bash
docker compose -f deploy/docker-compose.yml --env-file deploy/.env pull openchat
docker compose -f deploy/docker-compose.yml --env-file deploy/.env up -d
```

`up -d` recreates the container from the new image; a plain `restart` keeps running the old one. If `deploy/.env` pins `OPENCHAT_IMAGE` to a version, change it to `ghcr.io/qunqin24/openchat:1.1.2` first. No new database migrations.
