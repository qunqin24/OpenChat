v1.1.8 的补丁版本：活动记录里的文字也匀速淡入，以及「回到底部」按钮乱出现的问题。

*English summary below.*

## 修复

- **活动记录里的文字也匀速出现、新字淡入。** 搜索、读网页那一行展开后，里面的思考和中间说明以前还是一批一批直接冒出来（v1.1.8 漏了这里），现在和正文一样。
- **「回到底部」按钮不再乱出现。** 以前只要往上滚了一下滚轮、按了一下滚动条、在菜单或模型选择器里按方向键，即使画面没动、已经在最底部、或者对话短到不能滚，按钮也会出现，而且回答会停止自动跟随，后面的内容长到屏幕外面看不到。现在只有真的离开底部才出现、才停止跟随。

## 升级

在部署目录（仓库根目录）运行：

```bash
docker compose -f deploy/docker-compose.yml --env-file deploy/.env pull openchat
docker compose -f deploy/docker-compose.yml --env-file deploy/.env up -d
```

`up -d` 会用新镜像重新创建容器；只 `restart` 跑的还是旧版本。如果在 `deploy/.env` 里用 `OPENCHAT_IMAGE` 固定了版本号，先改成 `ghcr.io/qunqin24/openchat:1.1.9`。用 1Panel 等面板升级容器时，镜像写 `:latest` 要勾选「强制拉取镜像」，或直接写 `:1.1.9`。没有新的数据库迁移。

## English summary

A patch release for v1.1.8.

- **Fixed:** the thinking and notes inside the activity line (searches, pages read) still appeared batch by batch; they now get the same even pace and fade as an answer (v1.1.8 missed them).
- **Fixed:** the jump-to-bottom button appeared, and following the reply stopped, on any gesture up - a wheel tick, a press on the scrollbar, arrow keys in a menu or the model picker - even when nothing moved, the view was already at the end, or the conversation was too short to scroll. It now appears, and following stops, only once the view has actually left the end.

To upgrade, from the repository root:

```bash
docker compose -f deploy/docker-compose.yml --env-file deploy/.env pull openchat
docker compose -f deploy/docker-compose.yml --env-file deploy/.env up -d
```

`up -d` recreates the container from the new image; a plain `restart` keeps running the old one. If `deploy/.env` pins `OPENCHAT_IMAGE` to a version, change it to `ghcr.io/qunqin24/openchat:1.1.9` first. No new database migrations.
