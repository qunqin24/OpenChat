这一版修复 v1.3.1 引入的一个卡顿：**打开含有 Mermaid 图表的对话后往上滑，页面会卡住好几秒**。用 v1.3.1 的建议升级。

*English summary below.*

## 修复

- **图表不再让页面卡住。** v1.3.1 的「整批淡入」把消息渲染之后才画出来的图表整张当成了刚到的一批文字，给图上几百个标签逐个量位置、盖浮层，每一步都让浏览器重算整页样式；有 9 张图的对话里，往上滑时页面卡了约 5.5 秒。现在只有回答的文字真的变了才淡入，图表和公式里的字不盖浮层，位置先全部量完再统一写入，一次超过 4000 字的直接显示。同样的操作，最长一帧从 5.5 秒降到约 0.15 秒（剩下的是 Mermaid 画图本身）。

## 升级

在部署目录（仓库根目录）运行：

```bash
docker compose -f deploy/docker-compose.yml --env-file deploy/.env pull openchat
docker compose -f deploy/docker-compose.yml --env-file deploy/.env up -d
```

如果在 `deploy/.env` 里用 `OPENCHAT_IMAGE` 固定了版本号，先改成 `ghcr.io/qunqin24/openchat:1.3.2`。没有数据库迁移，不用改配置。

---

## English summary

This release fixes a freeze introduced in v1.3.1: **scrolling up in a conversation with Mermaid diagrams could lock the page for several seconds**. Everyone on v1.3.1 should upgrade.

- **Diagrams no longer freeze the page:** v1.3.1's batch fade took a diagram drawn after its message for a batch of newly arrived text, and measured and covered each of its labels one at a time, recalculating the page's style at every step; with nine diagrams, scrolling up froze the page for about 5.5 s. Now only new answer text fades in, text inside diagrams and formulas is never covered, every position is measured before any cover is written, and a batch over 4000 characters is shown as it is. The same scroll's longest frame went from 5.5 s to about 0.15 s (Mermaid drawing).

To upgrade, from the repository root:

```bash
docker compose -f deploy/docker-compose.yml --env-file deploy/.env pull openchat
docker compose -f deploy/docker-compose.yml --env-file deploy/.env up -d
```

If `deploy/.env` pins `OPENCHAT_IMAGE`, change it to `ghcr.io/qunqin24/openchat:1.3.2` first. No database migrations and no configuration changes.
