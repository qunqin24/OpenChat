v1.1.2 的补丁版本：回答跟随和滚动的几处修复、记忆更克制，以及升级后提示刷新页面。

*English summary below.*

## 新功能

- **升级后提示刷新。** 镜像升级、服务重启后，开着的页面会在右上角提示「服务端已更新，请刷新页面以使用新版本」，带「刷新」按钮。只有前端真的变了才提示，同一镜像重启不会提示；不会自动刷新，输入框里写了一半的消息不会丢。从这个版本起生效：页面要先加载过 v1.1.3，下一次升级时才会提示。

## 改进

- **记忆更克制。** 模型只在你让它记住（或忘掉、改正）时，或你明确说出关于自己的长期事实（职业、所在地、对回答方式的固定偏好等）时才存记忆；不再从你问过的话题推断兴趣，也不会把新事实不断追加进同一条记忆。「已更新记忆」的提示只显示更新后的内容。
- 对话最后一条消息下面留出和 Open WebUI 一样的空白，回答末尾和操作按钮不再贴着输入框。

## 修复

- 回答输出时页面一直贴着最新内容：以前会一路落后几行，回答结束后最后几行停在屏幕下面，切回正在输出的对话时也是这样。
- 点「回到底部」后会一直跟到回答结束，不再一按就断开。
- 输出过程中用触控板慢慢往上滑可以停住，不会被拉回底部。
- 新对话第一条消息还在发送时点「新对话」，会立刻回到空白页，那条消息在后台照常发完；之前离开的页面在后台完成时，不会再撤掉新页面刚发出的消息。

## 升级

在部署目录（仓库根目录）运行：

```bash
docker compose -f deploy/docker-compose.yml --env-file deploy/.env pull openchat
docker compose -f deploy/docker-compose.yml --env-file deploy/.env up -d
```

`up -d` 会用新镜像重新创建容器；只 `restart` 跑的还是旧版本。如果在 `deploy/.env` 里用 `OPENCHAT_IMAGE` 固定了版本号，先改成 `ghcr.io/qunqin24/openchat:1.1.3`。用 1Panel 等面板升级容器时，镜像写 `:latest` 要勾选「强制拉取镜像」，或直接写 `:1.1.3`。没有新的数据库迁移。

## English summary

A patch release for v1.1.2.

- **New:** after an upgrade, an open page says the server has been updated and offers a Reload button (only when the front end actually changed; it never reloads by itself, so a half-written message is kept). It takes effect from the upgrade after this one: the page must have loaded v1.1.3 first.
- **Memory is more restrained:** the model saves a note only when asked to remember, forget or correct something, or when the user states a lasting fact about themselves; it no longer infers interests from what was asked or keeps appending to one note. The "memory updated" notice shows only the new wording.
- **Room below the last message**, as in Open WebUI.
- **Fixes:** a streaming reply is followed to its last line (it used to trail by a few lines and leave the end below the screen, also after switching back to a conversation still answering); the jump-to-bottom button keeps following; a slow trackpad scroll upwards now leaves the end; "New chat" while a first message is still being sent goes straight to an empty page, and a page that was left no longer removes the first message of the page now on screen.

To upgrade, from the repository root:

```bash
docker compose -f deploy/docker-compose.yml --env-file deploy/.env pull openchat
docker compose -f deploy/docker-compose.yml --env-file deploy/.env up -d
```

`up -d` recreates the container from the new image; a plain `restart` keeps running the old one. If `deploy/.env` pins `OPENCHAT_IMAGE` to a version, change it to `ghcr.io/qunqin24/openchat:1.1.3` first. No new database migrations.
