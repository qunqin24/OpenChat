一次大的功能版本：子智能体、写作块、定时任务、文件库、按描述配图、通行密钥登录，以及一批聊天体验的改进。**游客模式已移除**，升级前请看文末的「升级」。

*English summary below.*

## 新功能

- **子智能体。** 主智能体可以把一件独立、费上下文的活（查一圈资料、读完一份长材料）交给子智能体，子智能体在自己的上下文里做完，只把报告交回来。可以前台等它，也可以转到后台、你继续和主智能体聊；主智能体还能中途给它发消息调整方向。顶栏「子智能体」按钮打开右侧面板，能看到每个子智能体在做什么、停止或继续它。同一对话同时运行的数量有上限，超出的排队。
- **写作块。** 让模型写文章、邮件、方案这类要反复修改的文字时，内容写进一个文档，在右侧面板里打开，你可以直接编辑、看历史版本、对选中的段落「提出修改请求」；模型修改时只改要改的地方。顶栏「写作」按钮列出这个对话里的所有文档，不用再往回翻。
- **定时任务。** 让模型在指定时间（一次、每天、每周、每月）以你的名义发出一段指令并回答，每个任务有自己的对话。可以在侧栏的「定时任务」页管理，也可以直接让模型帮你建。后台「系统」里可以整体关闭。
- **文件库与文本附件。** 现在可以发送文本文件（Markdown、CSV、代码、JSON 等），模型读到的是文字，任何模型都能收。侧栏「库」列出你发过的所有文件，可以搜索、下载、删除；文本文件点开直接在右侧面板里阅读。不同类型的文件有不同的图标。
- **按描述配图。** 打开后台「图片搜索」后，模型只需写出图片描述（例如 “laptop keyboard”），服务器去 Wikimedia Commons（默认）、Openverse 或 Pixabay（需要免费 Key）找一张自由授权的照片，下载保存后展示，同一描述始终是同一张；悬停可看来源和许可。不打开时和以前一样，只能用网页里出现过的图片。智能 UI 新增「左图右文」组件，步骤可以每一步配图，搜不到的图留一个浅色占位框保持对齐，点击图片可放大。
- **通行密钥登录。** 在「设置 → 账号」里添加通行密钥（指纹、面容或设备密码），之后在登录页点「使用通行密钥登录」即可，不用输入密码。后台新增「身份验证」页，通行密钥是其中一个标签页：可以开关、固定依赖方域名和允许的来源、设置用户验证要求。
- **请求轨迹。** 管理员可以在自己的对话里切换到「轨迹」视图，逐次查看每个模型请求实际发出的系统提示词、消息、工具和返回内容，便于调试。
- **删除账号。** 管理员可以在「用户」里删除账号（需输入账号名确认），对话、文件、记忆等一并删除；用量记录保留并标为「已删除的账号」。

## 聊天体验

- **引用提问。** 在回答里选中一段文字，点「引用提问」把它放进输入框再提问；一次最多引用五段，点引用卡片会在回答里高亮并跳到那一段。
- **隔了一段时间会提示时间。** 距离上一条消息一小时以上时，模型会被告知现在几点、隔了多久；页面上这条消息上方显示「今天 10:44」这样的时间。
- **链接样式。** 回答里的链接改为虚线下划线加 ↗，悬停显示网站图标、完整网址，以及打开、复制按钮。
- **智能 UI 提示词重写。** 按内容类型说明什么时候该用哪个组件、什么时候不用，减少花哨和多余的组件。柱状图类别多时标签斜放、不再跳过。
- 右侧面板（写作、子智能体、文件）可以拖动调整宽度并记住；面板打开、切换有过渡动画。
- 登录页标语改为「话一出口，世界便有了回声。」

## 修复

- 写作块：保存期间继续输入、或切换历史版本时，不再丢失刚输入的内容。
- 换账号后不再残留上一个人的图片查看器、引用和面板内容。
- 定时任务：编辑任务不再覆盖调度器刚推进的下次运行时间。
- 删除账号或渠道时，正在进行的请求的用量记录不再丢失。
- 审核拒绝的文档标题不会再出现在发给模型的内容里。
- 子智能体：重启后不丢报告、已删除的对话不会再启动子智能体、用户停止不会被并发消息撤销、排队的子智能体不会被启动两次，已取消的不会再被启动。
- 通行密钥：固定依赖方域名时不再信任请求自报的来源。

## 升级

在部署目录（仓库根目录）运行：

```bash
docker compose -f deploy/docker-compose.yml --env-file deploy/.env pull openchat
docker compose -f deploy/docker-compose.yml --env-file deploy/.env up -d
```

`up -d` 会用新镜像重新创建容器；只 `restart` 跑的还是旧版本。如果在 `deploy/.env` 里用 `OPENCHAT_IMAGE` 固定了版本号，先改成 `ghcr.io/qunqin24/openchat:1.2.0`。用 1Panel 等面板升级容器时，镜像写 `:latest` 要勾选「强制拉取镜像」，或直接写 `:1.2.0`。

**游客模式已移除（不兼容的改动）。** 登录页不再有「以游客身份使用」，`/guest/*` 接口全部删除。升级时的迁移会删除残留的游客临时账号和它们的对话、游客的审核记录、IP 封禁和游客相关设置；游客产生的用量记录保留，显示为「无账号」。

**有 9 个数据库迁移**，启动时自动按顺序执行：文件库、定时任务、请求轨迹、已删除账号的用量标记、写作块、子智能体、图片搜索、移除游客模式、通行密钥。

**通行密钥需要 HTTPS**（本地 `localhost` 除外），并且要确认 `CORS_ORIGINS` 是你访问站点的地址（Compose 部署默认是 `https://<DOMAIN>`）。站点不在依赖方域名本身、而在它的子域上时，请在 后台 → 身份验证 → 通行密钥 里填写允许的来源。

**按描述配图默认关闭**，在 后台 → 图片搜索 打开；找到的图片保存在文件存储的 `pictures/` 下。

## English summary

A large feature release. **Guest mode has been removed** — see Upgrading below.

- **Sub-agents:** the main agent can hand an independent, context-heavy task to a sub-agent, which works in its own context and returns only its report; in the foreground or the background, steerable mid-way. A side panel shows what each is doing, with stop and resume. A per-conversation limit queues the rest.
- **Writing blocks:** text you will keep refining (articles, emails, plans) is written into a document opened beside the chat — editable, versioned, with "ask for a change" on a selected passage; the model edits in place. A top-bar menu lists a conversation's documents.
- **Scheduled tasks:** a prompt sent in your name once, daily, weekly or monthly, each in its own conversation; managed from the sidebar or by asking the model. Can be switched off in System settings.
- **Library and text attachments:** send text files (Markdown, CSV, code, JSON…), read as text by any model. The library lists every file you sent; text files open in the side panel. Icons by file type.
- **Pictures by description:** with Image search on, the model describes a picture and the server finds a freely licensed photo on Wikimedia Commons (default), Openverse or Pixabay (free key), keeps it, and shows it with its credit. Off, answers show only pictures their sources listed, as before. New Media (picture beside text) component, pictures on steps, placeholders for pictures not found, click to enlarge.
- **Passkey sign-in:** add passkeys in Settings → Account and sign in without a password. A new admin Authentication page has a Passkeys tab (switch, relying party, origins, user verification).
- **Request traces** for administrators, **account deletion** in Users (usage kept, labelled).
- **Chat:** quote up to five passages of an answer into a question and jump back to them; the time is shown (and told to the model) when a message comes an hour or more after the last; links with a hover card; rewritten guidance on when to use each interface component; slanted bar-chart labels; resizable, animated side panels; a new sign-in tagline.
- **Fixes:** no lost writing-block edits when saving or switching versions; nothing of the previous account left after switching; task edits no longer overwrite the scheduler's next run; usage of in-flight requests kept when an account or channel is deleted; refused document titles kept from the model; several sub-agent stop, restart and queue races; passkey origins never taken from the request when the relying party is pinned.

To upgrade, from the repository root:

```bash
docker compose -f deploy/docker-compose.yml --env-file deploy/.env pull openchat
docker compose -f deploy/docker-compose.yml --env-file deploy/.env up -d
```

`up -d` recreates the container from the new image; a plain `restart` keeps running the old one. If `deploy/.env` pins `OPENCHAT_IMAGE` to a version, change it to `ghcr.io/qunqin24/openchat:1.2.0` first.

**Guest mode is removed (breaking):** the sign-in page no longer offers it and every `/guest/*` endpoint is gone. The migration deletes leftover guest accounts and their conversations, guest moderation entries, IP bans and guest settings; guests' usage rows are kept, shown as "no account". **Nine database migrations** run at startup: library, scheduled tasks, request traces, deleted-account usage labels, writing blocks, sub-agents, image search, guest-mode removal, passkeys. **Passkeys need HTTPS** (except on localhost) and a correct `CORS_ORIGINS`; if the site runs on a subdomain of the relying party ID, list the allowed origins in Admin → Authentication → Passkeys. **Pictures by description are off by default** (Admin → Image search); found pictures are kept under `pictures/` in file storage.
