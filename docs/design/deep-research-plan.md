# 深度研究：方案

> 状态：方案，未实现。目标是在只用免费搜索（`FreeSearch` 的 Exa / Parallel / Firecrawl / Keenable 免 key 轮换）的情况下，产出可信、带引用、结构完整的研究报告。和 [沙箱方案](sandbox-plan.md) 相互独立：深度研究不需要沙箱，报告里要画数据图表时才会用到它。

## 0. 结论先行

- **报告好不好，主要看花了多少 token、读了多少来源，搜索引擎本身影响不大。** Anthropic 的分析里，token 用量单独就解释了 BrowseComp 成绩差异的 80%，工具调用次数和模型是另外两个因素。所以免费搜索也能出好报告，前提是**少搜多读**：搜索只用来找入口，篇幅花在读一手来源上。
- **架构照 Anthropic 自己的 `deep-research` 技能来（§1.1）：主 Agent 只协调，并行的研究员把笔记存到外部，再由一个写作员读笔记写报告。** 我们已经有子 Agent、联网、写作块和后台 run，大部分是现成的。主要的新东西是：
  - 两种子 Agent 类型（研究员、写作员）和研究笔记；
  - 一个研究模式（提示词和预算）；
  - 一个**证据登记表**：引用只能指向服务端真的读到过的来源；
  - 一个**全站共享的搜索调度器**，因为免费额度按服务器 IP 计，全站用户共用。
- 报告写进写作块，用户能在应用里继续改，以后和文档一起导出 Word / PDF。

## 1. 别人怎么做的

| 做法 | 要点 | 我们取什么 |
|---|---|---|
| Anthropic Research（[原文](https://www.anthropic.com/engineering/multi-agent-research-system)） | 主 Agent 先想策略、把计划存到上下文外，再并行派 3–5 个子 Agent，每个子 Agent 又并行调 3 个以上工具；全部信息到齐后交给 CitationAgent 定位引用。Opus 主 Agent + Sonnet 子 Agent 比单 Agent 好 90.2%，但 token 是聊天的约 15 倍 | 整体架构；**按问题复杂度定规模**的规则；**交代任务四要素**（目标、产出格式、用什么工具和来源、边界）；**先宽后窄**的搜索；**子 Agent 产出存到外部、只回传引用**，避免层层转述走样 |
| STORM（Stanford） | 写之前先从多个视角提问、整理大纲，减少只写共识的偏差 | 大纲先行；按视角分配子 Agent |
| GPT Researcher | 计划一次性拆好，再并行抓取、缓存原文、先摘要再综合 | 抓取缓存；先摘要再综合 |
| LangChain open_deep_research | 迭代改写查询；写作者只能引用审过的来源 ID（citation registry） | **只能引用登记过的来源 ID** |

### 1.1 Anthropic 公开的研究提示词和技能

Anthropic 有三份相关材料，代表这套做法的两代：

| 材料 | 许可证 | 结构 |
|---|---|---|
| Cookbook 的 [`research_lead_agent.md`](https://github.com/anthropics/claude-cookbooks/blob/main/patterns/agents/prompts/research_lead_agent.md)、[`research_subagent.md`](https://github.com/anthropics/claude-cookbooks/blob/main/patterns/agents/prompts/research_subagent.md)、[`citations_agent.md`](https://github.com/anthropics/claude-cookbooks/blob/main/patterns/agents/prompts/citations_agent.md)：上面那篇文章里 Research 功能的生产提示词 | MIT | 第一代：主 Agent 自己写报告，写时**不带引用**；写完交给 CitationAgent，在**原文一字不改**的前提下补引用，改了字就整份作废 |
| Claude 自带的 `deep-research` 技能（claude.ai / Claude Code 里同步的那份，`SKILL.md` 加 `references/researcher.md`、`references/report-writer.md`） | 未开源，只能参考思路，不能照搬文字 | 第二代：协调者**既不研究也不写报告**，只拆题、派人、交付；研究员把笔记写进文件；**另派一个写作子 Agent** 读全部笔记写报告 |
| [claude-agent-sdk-demos/research-agent](https://github.com/anthropics/claude-agent-sdk-demos/tree/main/research-agent) | 仓库没写许可证，不照搬 | 演示版：研究员 → 数据分析员（用 matplotlib 画图）→ 写作员（出 PDF） |

技能版（第二代）最值得照着做的几点：

- **协调者的上下文保持干净。** 它不读研究笔记，只看每个研究员交回的简短小结，所以长研究不会把主对话撑爆。这正好对应我们的压缩和子 Agent 设计。
- **拆题要不重不漏（MECE），按类型定人数：**
  - 单一事实：1 人；
  - 聚焦的话题、几个角度：3 人；
  - 不同侧面或评价维度：4 人；
  - 多个独立实体或地区：5 人；
  - 大批可枚举的对象：6 人以上，按片区分。
  - 拿不准时默认 3 人。
- **交代任务的固定格式：** 研究什么、目标、关键问题、建议来源、约束（把原问题里的时间、地区限制传下去）、笔记存到哪。
- **补查最多一轮，而且必须在提示词里自我提醒。** 原话的意思是：再查就会超时或撞上限流，用户永远拿不到报告。这对免费搜索尤其重要。
- **研究员的预算：** 约 10 次工具调用，不超过 15 次。查询不超过 5 个词。搜到的结果一定要 fetch 全文，因为摘要容易断章取义。同一个查询不重复搜。
- **研究员的笔记格式：** 每个关键问题下面固定四段：
  - 要点（1–2 句）；
  - 带来源的发现（每条后面跟 `[来源](URL)`，矛盾的写「被某来源反驳」）；
  - 推断；
  - 缺口（查不到的写明查不到，**绝不编**）。
  没有来源的事实一律放进缺口。
- **追问只在会改变研究方向时才问：** 有歧义的术语、没说地区但答案因地区而异、同名实体。
- **报告格式：**
  - 约 6 个词、带动词的标题；
  - BLUF 开头段：读者看完这一段就能走；
  - 3–5 个「路标式」小标题（光看标题就懂结论，比如「候鸟每年多觅食 370 小时」，而不是「气候的影响」）；
  - 正文用叙述性段落、不用列表，关键数字加粗，行内引用；
  - 结论只写新的洞见，不复述。
  - **笔记里没有来源的重要论断不进报告**：5 条有出处的结论，好过 20 条一半没出处的。
- **续接旧研究：** 同一对话里追问时，起新标题，把上一份报告和笔记交给写作者作为基础，只研究新增的部分。

这套流程一份报告大约是 3–5 个研究员 × 10–15 次工具调用，再加至多一轮补查，算下来搜索大约 25–40 次，落在第 2 节的免费额度预算之内。

## 2. 免费搜索的限制，以及怎么绕开

现在的 `FreeSearch` 是四家免 key 服务轮流用，按调用方 IP 限流（`freesearch.go` 注释写明「meant for light use」）。一份深度研究要 30–100 次搜索，多个用户同时研究会更多，而**全站所有用户共用服务器这一个 IP**。所以：

1. **少搜多读。** 提示词和预算都往「读」倾斜：
   - 一次搜索的结果（后台「压缩」设置可以直接给正文）先读透；
   - 接着沿一手来源里的链接往下读（`web_fetch` 已经支持 `find`、`offset`）；
   - 不为换个说法再搜一遍。
2. **全站搜索调度器**（新，在 `tools` 包里包住 `Searcher`）：
   - 每家服务一个令牌桶和并发上限，**全进程共享**，按各家实际限流调；
   - 某家回 429 或拒绝时，按它给的时间冷却，期间轮换跳过它（现在只跳过当次）；
   - 全部冷却时，工具结果里写明「搜索暂时受限，约 N 秒后恢复；先读已有的来源」，让模型改去读，不卡住、不重试风暴。
3. **搜索结果缓存**：
   - 键是规范化后的「查询 + recency + sites」，留 24 小时，放在库里，进程重启和多实例都能用；
   - 网页不带 cookie，结果不分人，所以可以跨用户共享；
   - 同一次研究里两个子 Agent 搜了同一个词，第二次直接命中，结果里注明「已搜过」，提示它换个角度。
4. **每次研究有预算**：搜索次数和读网页次数（建议 60 / 150，后台可调）。剩余额度在每轮的轮次说明里告诉主 Agent 和子 Agent，用完了工具就拒绝，并说明原因。
5. **可选的免费垂直来源**（后期）：维基百科、arXiv、OpenAlex/Crossref、GitHub、Hacker News（Algolia）、Stack Exchange 等，有公开 API、免 key 或 key 免费，质量比通用搜索高，也不占四家的额度。做成 `web_search` 的 `source` 参数或单独的工具，到时候再定（这些服务的免 key 限额要逐一核实）。
6. **管理员可以加后端**：`Searcher` 接口已经能换。可选接入：
   - 自托管 SearXNG：要注意机房 IP 常被 Google、DDG 屏蔽，可能返回 200 但结果为空，调度器要把「空结果」算作失败；
   - Tavily 免费 key（每月 1000 次）；
   - LangSearch 免费 key。
   加进轮换就能分摊压力。

## 3. 流程

用户在输入框打开「深度研究」开关（和「联网」并列），或者模型判断需要时建议用户打开。不让模型自己悄悄进入：它比普通回答贵一个数量级。

照 Anthropic 技能版（第二代，见 §1.1）的分工：**主 Agent 只协调，研究员研究，写作员写**。

```
1. 追问（可选）  只在歧义会改变研究方向时用 ask_user 问一次，然后不再打断
2. 拆题          主 Agent 定标题、按 MECE 拆子题、按 §1.1 的表定人数；子题列表显示给用户当作进度
3. 并行研究      同一轮派出全部研究员（前台子 Agent，研究员类型）。每人约 10 次、至多 15 次工具调用；
                 边读边用 evidence_add 登记证据，最后把固定格式的笔记存进研究笔记（不是塞进给主 Agent 的报告）；
                 交回主 Agent 的只有几行小结
4. 补查（至多一次）  主 Agent 只看小结里的「缺口」，非补不可才再派一轮；之后无论结果如何直接进入写作
5. 写作          派一个写作员子 Agent：读全部笔记和登记表，按 §1.1 的报告格式写进写作块，
                 行内引用只能写登记过的编号 [S12]；笔记里没来源的论断不写
6. 核对（第 2 期）  核对子 Agent 拿每条 [S#] 对应的原文摘录，检查是否支持那句话，列出不支持的；
                 写作员用定点修改改掉或删掉
7. 交付          主 Agent 在回复里写 3–5 句摘要，附上写作块卡片；报告末尾是来源列表
```

整个流程是**一次 run 里的提示词约定加工具**，不是写死的状态机（Anthropic 的经验是写好启发式，不要硬编码路径）。服务端只管预算、登记表和引用编号的有效性。

现有子 Agent 要补的东西：

- **子 Agent 类型**：「研究员」和「写作员」，各有自己的系统提示词和工具白名单。现在子 Agent 只有一种。
- **研究笔记**：一次研究一份，挂在 run 上随回答删除。研究员用 `notes_save` 写自己那一节，写作员用 `notes_read` 读全部。主 Agent 不读，保持上下文干净。这就是 Anthropic 说的「子 Agent 产出存到外部，只回传引用」。
- **写作员能写写作块**：现在子 Agent 对写作块只读。写作员要能 `create` 和 `update` 这一次研究的报告，其他文档仍然只读。
- **续接**：同一对话里追问时，主 Agent 把上一份报告的 id 交给写作员作为基础，研究员只查新增的部分。

## 4. 提示词要点（英文，三份：协调者 `researchGuide`、研究员、写作员）

提示词自己写，结构参照 Cookbook（MIT，可以改编，注明出处）和技能版的思路（未开源，不照搬原文）。

- **规模规则**：用 §1.1 那张按类型定人数的表，默认 3 人，上限受后台 `MaxPerRun` 管。
- **交代研究员的模板**：研究什么、目标、关键问题、建议来源、约束（时间、地区）、优先哪类来源。笔记格式由研究员的系统提示词固定，不靠协调者每次交代。
- **补查只有一次**：协调者提示词里写明原因，即会超时、会撞上免费搜索的限流。
- **先宽后窄**：先用短而宽的查询看全貌，再收窄；技术和国际话题用英文搜，中国话题用中文搜，必要时两种都搜。
- **来源质量**：一手来源（官方文档、论文、财报、原始数据、当事人的博客）优先于聚合站和 SEO 内容农场；记下发布日期；重要事实要两个独立来源印证，矛盾就写出来。
- **写作**：结论先行；每节回答一个子问题；数字带单位和日期；不确定的写明不确定；不写来源里没有的东西。
- 模型用错工具时改提示词或工具描述，不在服务端改写它的输出。

## 5. 证据登记表（新）

一次研究一张表：`research_sources`（挂在 run 上，`ON DELETE CASCADE`，和写作块一样随回答被改写、重新生成而消失）。

- **登记**：新工具 `evidence_add`（url, quote, claim, published?），主 Agent 和研究中的子 Agent 都可以用。服务端检查：
  - 这个 url 是本次研究里 `web_fetch` 真读过的页面，或 `web_search` 返回过正文的结果；
  - `quote` 确实出现在读到的正文里（规范化空白后做子串匹配）。
  两条都满足才登记，返回编号 `S12`，否则拒绝并说明原因。**这样引用的链接一定存在，摘录一定是原文**，在结构上消掉了「编造来源」这一类错误。
- **读回**：`evidence_list` 按子问题或关键词列出已登记的证据，主 Agent 写作时用。子 Agent 的报告只需写结论和编号，原文留在表里，不在报告里层层转述。
- **显示**：写作块里的 `[S12]` 是我们定的引用格式（和 `<document-selection>` 一样是格式约定，不是改写模型输出），前端渲染成角标，悬停显示标题、站点、日期和摘录，点开跳原网页；导出时变成脚注。报告末尾的来源列表由前端按编号生成。
- **核对**：第 7 步的核对子 Agent 读的就是这张表，不重新抓取，便宜。

存的只有 url、标题、日期、不超过约 500 字的摘录和对应的论断，不存整页。

## 6. 产品与界面

- **开关**：输入框「深度研究」，和联网一样按对话记。打开后本次 run 的 `MaxToolRounds` 提高（如 200），并提供研究工具。后台开关 `deep_research` 默认开，可以限制每人每天的次数。
- **进度**：回复里一张研究卡片，显示：
  - 计划（子问题列表，完成的打勾）；
  - 每个子 Agent 在查什么（复用现有子 Agent 卡片）；
  - 已读来源数、已登记证据数、用掉的预算。
  这比一串工具调用更能让用户看懂它在做什么。
- **后台**：run 本来就在服务端，关掉网页也会继续，回来看结果；完成时通过 App 推送、浏览器通知提醒（如果有）。
- **报告**：写作块。用户能直接改，也能选中一段「提出修改请求」让它补查；导出 Word / PDF 随文档导出一起做。
- **时长**：目标 5–15 分钟。超时、预算用尽时也必须交一份「目前为止」的报告，并写明没查完的部分。

## 7. 成本与上限

- token 约为普通聊天的 15 倍。子 Agent 用后台设置的子 Agent 模型（便宜的），主 Agent 用用户选的模型。
- 用量照常记：子 Agent 的 run 已经是 `subagent` kind；主 run 是 `chat`，可以考虑加 `research` kind，便于后台单独统计。
- 容量上限、`pickChannel`、`failover` 全部沿用，不另开路径。

## 8. 评测

先有评测再调提示词（Anthropic：20 条真实问题就能看出大部分改动的效果）：

- 准备 20 条覆盖不同类型的研究问题（中英文、时效性、对比、综述、冷门事实）；
- 用 LLM 评分，按这几项打分：事实准确、引用准确（引用是否支持论断）、完整、来源质量、工具效率；
- 另记机器指标：搜索次数、读网页次数、命中缓存比例、被限流次数、耗时、token；
- 人工抽看，重点看是否偏爱内容农场、是否有来源没说过的话；
- 真实模型测试按约定用 Claude Haiku 5.5。
