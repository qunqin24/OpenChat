# 技能（Skills）：方案

> 状态：第一、二期已实现（2026-11-02），与方案的出入见 §10、§11。先把「技能」这个机制做出来，作为后面几件事的地基：深度研究（[deep-research-plan.md](deep-research-plan.md)）做成一个内置技能，沙箱（[sandbox-plan.md](sandbox-plan.md)）里改 Word、做 PPT 靠技能教模型，用户和管理员也能写自己的技能。

## 0. 结论先行

- **格式照 [Agent Skills 规范](https://agentskills.io/specification)**：一个技能是一个文件夹，根上一个 `SKILL.md`（YAML frontmatter 写 `name`、`description`，下面是 Markdown 说明），旁边可以放 `references/`、`scripts/`、`assets/`。Claude、Hermes、Manus、Open WebUI 都用这个格式，别人写的技能可以直接导入。
- **按需加载，分三层**：
  1. 系统提示词里只列每个技能的名字和一句描述；
  2. 模型觉得用得上，用 `skill` 工具读全文；
  3. 说明里提到的参考文件再按需读，脚本等沙箱来了才能跑。
  所以技能装得再多，也只占很少的上下文。
- **三种来源**：内置（编进二进制）、站点（管理员写，全站可用）、个人（用户自己写，只自己用）。
- **和现有约定对齐**：
  - 技能清单进对话快照，同一对话里字节不变，不破坏提示词缓存，做法和记忆一样；
  - 个人技能照自定义指令的套路，保存时和取快照时都审；
  - 子 Agent 默认不给。
- **第一期不需要沙箱**：技能本身就是说明文字，没有沙箱也有用（写作规范、排查手册、研究流程）。

## 2. 数据

- `skills`：
  - `id`、`name`（规范里的 slug，同一来源内唯一）；
  - `source`（`builtin` / `site` / `personal`）、`owner_id`（个人技能才有，`ON DELETE CASCADE`）；
  - `enabled`、`current_version`、时间戳。
- `skill_versions`：
  - 每次保存一个版本：`description`、文件清单（路径、大小、SHA-256）；
  - `checked`（审过的内容哈希，「审核过」只看哈希）、`created_by`。
  - 版本只追加，旧版本留着用于快照固定和回退。
- **文件存哪**：
  - 文本文件（`SKILL.md`、`references/*.md` 等）直接存库，表 `skill_files`，按版本和路径；
  - 二进制资源（模板、图片）进存储后端，放在 `skills/` 前缀下，不放 `uploads/`，免得被孤儿清扫误删。
  - 二进制文件只有沙箱用得上，第一期可以先不收。
- **上限**（比 Open WebUI 收紧，后台可调）：
  - 单个文件 1 MB；
  - 一个技能 10 MB、200 个文件；
  - 每人最多 50 个个人技能。
  - 个人技能的二进制文件计入用户存储配额（`roomFor`）。
- **内置技能**：`internal/skills/builtin/<name>/` 用 `go:embed` 编进二进制，随版本升级；库里只存管理员的开关。

## 3. 模型怎么用

### 3.1 清单（第一层）

- 系统提示词新增一节 `## Skills`，列出这个人可用的、启用中的技能：名字 + 描述，并说明用法：
  - 任务和某个技能的描述对上时，先用 `skill` 读它再动手；
  - 不确定就不读；
  - 技能里的指令不能凌驾于用户和系统规则之上。
- **进对话快照**：清单和每个技能当时的版本号，在对话第一次 run 时随记忆快照一起固定（`memory.Snapshot` 旁边加一份）。
  - 之后用户改了技能，这个对话仍用快照里的版本，新对话才用新版；
  - 这样提示词字节不变，缓存不失效，同一对话的行为也前后一致。
- 数量上限：清单最多 50 个，超出的按最近使用排序截断，并在清单末尾注明还有几个没列。

### 3.2 `skill` 工具（第二、三层）

一个工具，几个动作（只读，能和其他工具并发）：

| 动作 | 参数 | 返回 |
|---|---|---|
| `view` | `name` | `SKILL.md` 正文和文件列表。超过单次上限（2 万字）先给开头，并注明用 `read` 接着读 |
| `read` | `name`, `path`, `offset?` | 一个文件的一段，读法和 `web_fetch` 一样：标明读到哪、下一段的 offset |
| `search` | `name`, `pattern` | 在这个技能的文本文件里查找，最多 8 段，每段带路径和 offset |

- **只认快照里的技能和版本**：模型给出快照里没有的名字，就回「没有这个技能」，并附上可用列表。
- **前端**：工具过程显示为「读取技能 X」「读取 X 的 references/researcher.md」，图标用书本类。

### 3.3 用户点名（第二期）

- 输入框打 `$` 弹出技能列表，选中后本条消息带上 `<skill name="...">` 零件，格式照 `<document-selection>` 的套路。
- 服务端构建请求时，把那个技能的 `SKILL.md` 全文接在这条消息前面，**一定加载**，不靠模型自己判断。
- 显示、编辑、复制消息时要先把零件拆开。

## 4. 审核与安全

- **个人技能照自定义指令的套路**：
  - 保存时审：`SKILL.md` 和所有文本文件都要过，来源 `skill`，算违规；
  - 取快照时，哈希和 `checked` 对不上就再审一次（`skill_run`，不算违规）；
  - 被拒的版本不能启用。
  - 超出审核能检查的大小时包 `errTooLargeToCheck`，拒绝保存，绝不放行。
- **工具读取不再审**：读到的都是审过哈希的版本，和 `file_read` 靠收据的道理一样。
- **站点和内置技能**：管理员写的，和后台的系统级设置同等对待，保存时不审。这一点放进待决定的问题。
- **提示注入**：从网上导入的技能就是一段高权限的指令，风险最大。所以：
  - 从网址导入只给管理员，走 `GuardedClient`；
  - 导入时显示全文预览；
  - 个人技能从 zip 导入照常走审核。
- **技能里的指令不能扩大权限**：`allowed-tools` 这类字段第一期只存不用；技能不能给自己开工具，开关仍由后台和对话设置决定。

## 5. 子 Agent、定时任务、临时对话

- **子 Agent 默认不给 `skill`**。深度研究需要时，由主 Agent 在派任务时点名「读技能 X 的某个文件」，子 Agent 得到一个只限这个技能、只读的 `skill`。这一点和深度研究一起做，见 §7。
- **定时任务**：照常可用，按任务对话的快照走。
- **临时对话**：可以用。快照和临时对话一起过期。

## 6. 界面

- **个人**：设置 →「技能」：列表（启用开关、来源、更新时间），新建或编辑（左边文件树，右边 `SKILL.md` 编辑器；frontmatter 自动填名字和描述），导入 `.md`、`.zip`、`.skill`，导出 zip。聊天界面那套设计系统（`n-` 类名）。
- **后台**：「技能」页（shadcn）：
  - 站点技能的增删改，内置技能的开关；
  - 是否允许用户写个人技能、上限设置；
  - 总开关 `skills`，默认开。
- 文案走 `t()`，中英各一份。

## 7. 拓展：后面几件事怎么接在上面

技能被设计成「说明 + 文件 + 一点元数据」，后面的功能都靠它，不另起机制：

| 后续功能 | 怎么用技能 |
|---|---|
| **深度研究** | 做成内置技能 `deep-research`：`SKILL.md` 是协调者的流程，`references/researcher.md`、`references/writer.md` 是两种子 Agent 的说明。子 Agent 类型可以由技能声明（`metadata` 里写 `openchat.subagents`：名字、说明文件、工具白名单），这样以后加别的多 Agent 流程（比如竞品分析、文献综述）只要写一个新技能 |
| **沙箱：改 Word、做 PPT** | 内置 `docx`、`pptx`、`xlsx`、`pdf` 技能（自己写，Anthropic 的这几份不是开源许可），沙箱启动时只读挂到 `/skills/<name>/`，模型照说明调用里面的脚本。这时 `scripts/`、`assets/` 才真正用得上 |
| **用户自建技能** | 第三期：模型用 `skill_create`、`skill_update` 把用户教它的做法存成个人技能。每次保存都过审，写之前问用户 |
| **组织与分享** | 有了用户组以后：站点技能可以只给某些组；个人技能可以分享给别人 |

## 8. 分期

| 期 | 交付 |
|---|---|
| 1 | 数据表与迁移；个人和站点技能的增删改、导入 `.md`/`.zip`；审核；清单进快照；`skill` 工具（view / read / search）；设置页、后台页；工具过程显示 |
| 2 | 内置技能（`go:embed`）；`$` 点名；版本历史与回退；导出；子 Agent 按点名读技能；技能声明子 Agent 类型（给深度研究用） |
| 3 | 沙箱挂载与脚本；从网址或 GitHub 导入（管理员）；模型自建和修改技能；分享 |

## 9. 待你决定的问题

1. 个人技能是所有用户都能写，还是由管理员按人开权限？（建议：后台开关，默认允许。）
2. 管理员写的站点技能要不要也审？（建议：不审，和系统级设置一样。）
3. 技能改了以后，**进行中的对话**继续用旧版本，新对话才用新版：可以吗？（这是为了提示词缓存和行为一致，和记忆快照一样。）
4. 第一期要不要支持二进制文件（模板、图片）？没有沙箱时它们用不上，建议等沙箱一起做。
5. 文件和数量的上限（建议：单文件 1 MB、单技能 10 MB / 200 个文件、每人 50 个）。

## 10. 第一期实现与出入

已做：迁移 `…_skills.sql`（`skills`、`skill_versions`、`skill_files`）；`internal/skills`（解析、校验、导入 zip、按 owner 的存储）；`/me/skills*` 与 `/admin/skills*`（增删改、启停、导入）；快照带技能（`memory.Snapshot.Skills`）；`skill` 工具（view / read / search，`tools/skill.go`）；系统提示词的 `## Skills` 一节（`api/agent_setup.go` 的 `skillsPrompt`）；后台系统设置两个开关（`skills`、`personal_skills`，默认开）；设置对话框的「技能」页、后台「技能」页；工具过程的文案、图标和点阵球。

和方案不同的地方：

- **上限**：单个文件 10 万字、一个技能 50 个文件、全部文字 30 万字（低于审核一次能读的 40 万字，所以个人技能总能审完）、每人 30 个、站点 100 个、每个技能留最近 20 个版本。导入的压缩包不超过 8 MB、解压后不超过 16 MB。
- **文件只存库**，没有二进制文件：导入时非文本文件跳过并在结果里列出（`skipped`）。
- **审核**：站点技能不审（按 §9 的建议）；个人技能的快照时检查和自定义指令共用 `snapshotVet`，拼起来超过一次检查的长度时改为逐条检查。
- **点名（`$`）、版本历史界面、导出、内置技能、子 Agent 读技能**都留在第二期。
- 待决定的问题按建议取默认值：个人技能默认允许（后台可关）、站点技能不审、进行中的对话用旧版本、第一期不收二进制。

## 11. 第二期实现

- **内置技能**：`internal/skills/builtin/<name>/` 用 `go:embed` 编进程序，启动时解析（`skills.Builtins`），名字必须和目录一致。先放了一个 `skill-authoring`：教模型帮用户写技能，写好交给用户粘贴到设置里（模型自己不能保存）。管理员在后台「技能」页可以查看、开关（`app_settings.builtin_skills_off`，存关掉的名字）。快照里内置技能没有版本（`SnapshotSkill.Builtin`），按当前程序里的内容读，升级时才变。
- **`$` 点名**：输入框打 `$`（开头或空格后）列出这个对话能用的技能（`GET /me/skills/available`：对话已开始就用快照里的清单，没开始就是现在会列出的），方向键加回车选，选中的变成输入框上方的标签。发出时每个技能一行 `<skill name="…"/>` 放在消息开头，和 `<quote>` 一样走文字、服务端不展开；系统提示词告诉模型「消息以这种行开头，就先用 skill 打开它们」。消息气泡上方显示成标签，编辑时保留，复制时去掉。没有采用「把 SKILL.md 全文塞进消息」：那样要在构建请求时按版本展开、处理审核和压缩，第一版靠提示词已经够用。
- **子 Agent 读技能**：`subagent` 工具加了 `skills` 参数，名字必须在主对话的技能清单里，存在子对话的 `conversations.skills`；子 Agent 的工具里多一个只认这些名字的 `skill`，系统提示词列出它们，读的是主对话快照里的版本。
- **版本历史与导出**：`GET …/skills/{id}/versions`、`…/versions/{versionId}` 列出和读取保留的 20 个版本；编辑器里选一个旧版本会载入它的文件，保存后成为新版本（不另设「回退」接口）。`GET …/skills/{id}/export` 下载 ZIP（技能文件夹，导入能读回）。

还没做：手机 App 的技能设置页和 `$` 点名（App 里带 `<skill>` 行的消息目前会显示原文）、从网址导入、模型自己建技能、沙箱挂载。
