# 插件（技能 + MCP）：方案

> 状态：第一期进行中。已做：插件目录与安装（`api/plugins.go`）；侧栏「插件」页；后台「插件」页（增删改、启停、图标、MCP 地址与认证方式、OAuth 应用、拉取工具、按工具三档权限，`api/plugins_admin.go`）；内置插件（GitHub）；`internal/secrets`（密钥自动生成在 `data/secret.key`）；`internal/plugins`（官方 Go SDK 列工具；OAuth 发现、动态注册、PKCE、换取与刷新令牌）；每人连接账号（`api/plugins_oauth.go`）。还没做：对话里调用插件工具、确认卡片、插件技能、Client ID Metadata Document。

## 0. 结论先行

- **插件 = 技能 + MCP 连接。** 一个插件可以带一个远程 MCP 服务（模型能调用的工具）、若干技能（模型怎么用这些工具、怎么做这类事），或者两者都有。比如「GitHub 插件」：GitHub 的 MCP 工具，加上「怎么写 PR 描述」「怎么分诊 issue」两个技能。用户启用插件，就同时得到工具和用法。
- **管理员添加，用户自己挑选安装。** 管理员配一次 MCP 地址和认证方式，插件进入「插件」页；用户在侧栏「插件」页里挑选安装（2026-11-03 定），需要账号的服务（GitHub、Notion……）安装时用自己的账号授权（OAuth），模型只能以这个人的身份做事。装上的插件在他的对话里可用。
- **只接远程 MCP（Streamable HTTP）**，不在服务器上跑本地命令（stdio）。本地 MCP 等[沙箱](sandbox-plan.md)来了再说。
- **写操作默认要用户确认。** 工具没标 `readOnlyHint` 就当它会改东西，调用前停下来让用户点「允许」（和 `ask_user` 同一套「用户回答的工具」机制）。管理员可以按工具设「始终允许 / 需确认 / 禁用」。
- **用户的第三方令牌加密存储**（新环境变量 `OPENCHAT_SECRET_KEY`，§5）。
- **管理员加的插件可以连内网**：自托管时接公司内部系统是主要用途。
- **工具多了不全塞给模型。** 第一期按对话勾选启用哪些插件、单个插件的工具数封顶；第二期做工具搜索或 CodeMode（§8）。

## 1. 别人怎么做

| 产品 | 做法 | 我们取什么 |
|---|---|---|
| ChatGPT（Apps / 开发者模式里的自定义 MCP） | 远程 MCP；写操作默认要确认，没标 `readOnlyHint` 的工具都当写操作；可以「记住这次批准」，换对话重新问 | 写操作确认、默认按写操作处理 |
| Claude（自定义连接器） | Team/Enterprise 由 Owner 添加，成员各自连接、各自启用；Owner 按工具设「始终允许 / 需确认 / 禁用」；Research 模式会自动调用工具，官方建议研究时关掉写工具 | 管理员加、用户各自授权；按工具的三档权限；深度研究只给只读工具 |
| Open WebUI（v0.6.31 起原生 MCP） | 只支持 Streamable HTTP（理由是多租户的 Web 架构）；只有管理员能加；OAuth 2.1 支持动态注册和预先注册的 client | 只接 Streamable HTTP；只有管理员能加；OAuth 两种注册方式 |
| Claude Code 插件 | 一个插件打包技能、MCP 服务器、命令、钩子，装上就都有了 | 「插件 = 技能 + MCP」的打包 |
| OpenCode CodeMode | MCP 工具不直接列给模型，模型写一段 JS 在受限解释器里调工具、组合结果，只交回最终值；工具太多时用 `search()` 查目录 | 第二期的工具过多方案（§8） |

## 2. 插件由什么组成

后台「插件」页里，一个插件有：

- **基本信息**：名称、短名（工具名前缀，`[a-z0-9-]`）、图标、一句话说明（给用户看，也给模型看）。
- **MCP 连接**（可选）：地址、认证方式（§5）、工具清单（拉取后逐个设权限）。
- **技能**（可选）：插件自带的技能，格式和站点技能一样（`SKILL.md`，可以导入 zip），在插件页里编辑；版本照技能的规则保存。插件的技能只在插件启用时进入对话的技能清单。
- **谁能用**：所有人 / 只有管理员（以后接用户组）。
- **开关**：停用后所有对话都拿不到它的工具和技能，用户的授权保留。

只有技能、没有 MCP 的插件也成立（相当于一组打包的站点技能，但能按对话开关）；只有 MCP、没有技能的也成立。

站点技能（后台「技能」页）和插件的技能是两回事：前者对所有对话可见，后者跟着插件开关。以后可以考虑把站点技能都收进插件，第一期不动。

### 2.1 内置插件与图标（2026-11-03）

- **内置插件**定义在 `internal/plugins/builtin.go`，每次启动时补上库里还没有的（`plugins.builtin` 记定义的键），**默认关闭**：要等管理员把自己那部分配好（比如 GitHub 的 OAuth App）再打开。管理员可以改、可以关，不能删（409 `plugin_builtin`）；短名已被管理员自己的插件占用时跳过。
- 第一个内置插件是 **GitHub**：官方托管的 MCP 服务 `https://api.githubcopilot.com/mcp/`，每人用自己的账号授权。实测它的受保护资源元数据指向 `https://github.com/login/oauth`，GitHub 不支持动态注册客户端，所以管理员要先在 GitHub 上注册一个 OAuth App（回调地址指向本站），等账号授权做好后在后台填 client ID 和 secret。
- **图标**用 Simple Icons（simpleicons.org，CC0，npm `simple-icons`）。后台表单里按名字搜索挑选，图标库约 5 MB，只在打开挑选框时按需加载；选中后把 slug、SVG 路径和品牌色存进插件（`icon_slug`、`icon_path`、`icon_color`），用户的插件页直接画存下的路径，不加载图标库。路径只允许 SVG 路径命令和数字（服务端校验）。图标画在品牌色的方块上，浅色品牌用深色图形（`lib/plugin-icon.ts`）。没有图标时显示标志文字。内置插件的图标在后来的版本里补上时，只填给还没有图标的行，不覆盖管理员选的。

## 3. 范围

第一期：

- 传输：Streamable HTTP（MCP 规范 2025-06-18 起的标准远程传输）。老的 HTTP+SSE 传输不做。
- MCP 能力：只用 **tools**（`tools/list`、`tools/call`）。resources、prompts、elicitation（服务器反问用户）、sampling（服务器借用模型）、MCP Apps（工具带交互界面）放到后面（§10）。
- 认证：无认证、固定请求头、每人 OAuth（§5）。

不做：用户自己添加插件、stdio 本地服务器、把 OpenChat 自己暴露成 MCP 服务器（另一件事）。

## 4. 管理员和用户各做什么

- **管理员**（后台 → 插件）：增删改插件；拉工具清单，逐个工具设权限（默认按 `readOnlyHint` 给：只读的始终允许，其余需确认）；看调用日志。
- **用户**（侧栏「插件」页，在「定时任务」下面）：浏览管理员添加的、自己能用的插件，搜索、按「全部 / 已安装」筛选；点「安装」，需要账号的接着走 OAuth 授权，授权完成才算装上；已安装的可以看详情（连接状态、工具和各自的权限、自带的技能）、断开账号、卸载。卸载删掉他的令牌和安装记录。页面样式见效果图（三版待选）。
- **没连接时**：插件在对话里显示「未连接」，模型调用时返回「用户还没连接 X，请提醒他去设置 → 插件里连接」，不在对话中途弹登录（Open WebUI 的坑：后台没法替用户发起浏览器登录）。对话里的插件开关旁边直接给「去连接」的入口。

## 5. 认证与令牌

- **无认证**：内部服务或公开服务。
- **固定请求头**：管理员填 `Authorization: Bearer …` 之类，所有人共用一个身份。适合只读的公共数据源；写操作要慎用，因为所有人都以同一个身份写。管理员填的这个值也加密存储。
- **每人 OAuth**：按 MCP 授权规范走 OAuth 2.1 + PKCE：
  - 先请求 MCP 地址拿 401，读 `WWW-Authenticate` 里的受保护资源元数据（RFC 9728）找到授权服务器，再读授权服务器元数据；
  - 客户端注册优先用 **Client ID Metadata Document**（我们在 `https://<站点>/oauth/client.json` 放一份客户端元数据，用这个网址当 client_id，2025-11 版规范起的首选）；不支持就退到**动态注册**（RFC 7591）；都不支持就让管理员填预先注册的 client_id/secret；
  - 回调地址 `https://<站点>/api/plugins/oauth/callback`，`state` 一次性、绑定用户和插件，带 `resource` 参数（RFC 8707）；
  - 存 access token、refresh token、过期时间；过期前自动刷新，刷新失败标记为「需重新连接」。

**已实现的连接流程**（2026-11-03，`api/plugins_oauth.go`、`internal/plugins/oauth.go`）：

- 插件页点「去 XX 授权」→ `POST /plugins/{id}/connect`：先发现授权服务器（请求 MCP 地址拿 401 里的 `resource_metadata`，再试 `/.well-known/oauth-protected-resource{path}`；授权服务器元数据按 RFC 8414 的插入路径、再按 OpenID 的两种位置找）。服务返回的地址只在 https 或与 MCP 地址同主机时才跟；授权服务器声明了 PKCE 方法却没有 S256 就拒绝。
- 客户端：管理员填的 Client ID/Secret（Secret 加密保存），没填且服务器有 `registration_endpoint` 就当场动态注册并存下来（`oauth_registered`），都没有就 409 `plugin_oauth_unconfigured`。GitHub 不支持动态注册，必须在 GitHub 上注册 OAuth App，回调地址填后台显示的 `<站点>/api/v1/plugins/oauth/callback`。还没做 Client ID Metadata Document（要有固定的公网地址）。
- 授权地址带 PKCE（S256）、`state`、`resource`（RFC 8707）和管理员设的 scope；`state` 只存 SHA-256，PKCE verifier 加密保存，10 分钟有效、只能用一次、只能由发起的那个人取（`plugin_oauth_states`，清扫循环删过期的）。
- 回调 `GET /plugins/oauth/callback`：取走 state，有 `iss` 时核对是不是同一个授权服务器（RFC 9207），换取令牌，加密存进这个人的安装记录（`plugin_installs.access_token`/`refresh_token`/`token_expires_at`），装上插件，跳回 `/plugins?connected=<短名>`；失败跳回 `?connect_error=<原因代码>`，页面按代码显示，不回显服务器的原话。
- 令牌快过期时用 refresh token 换新的；刷新被拒就标记 `needs_reconnect`，插件页提示重新连接。
- 后台「拉取工具」对每人授权的插件用管理员自己的连接（先在插件页装上），没连接就 409 `plugin_not_connected`。

**加密存储**（2026-11-03 定，同日改为自动生成密钥）：

- 用户的 access/refresh token、管理员填的固定请求头和 OAuth client secret，都用 AES-256-GCM 加密后入库，库里只有密文。
- 密钥首次启动时自动生成，写进数据目录的 `data/secret.key`（只有服务器的用户能读，已 gitignore；Docker 里在 `/app/data` 卷上）。设了环境变量 `OPENCHAT_SECRET_KEY`（32 字节，base64）就用它，不读文件。
- 不放进数据库：密钥和密文放在一起，数据库导出泄露时等于没加密。所以备份要把数据目录和数据库一起备份；只恢复数据库，所有凭证都解不开，用户需要重新连接，管理员要重新填请求头。
- 文件写不进去（目录只读）时插件凭证功能不可用，后台插件页提示原因，其他功能照常；文件存在但内容不对则拒绝启动，免得新存的凭证用错的密钥加密。
- 密文带密钥版本号，以后可以轮换。
- 渠道的 API Key 现在是明文存库的，第一期不动；以后可以用同一把密钥迁移过去。

## 6. 在对话里

- **启用哪些**：用户装上的插件在他所有对话里可用（`plugin_installs` 表，按用户）。以后如果一个人装得多、工具超上限，再加按对话开关（「+」菜单里的「插件」）。
- **技能**：启用的插件带的技能加进这个对话的技能清单，版本在第一次启用时记进对话快照（和站点技能同一套规则，同一对话内字节不变）。
- **工具命名**：模型看到的工具名是 `<插件短名>__<工具名>`（如 `github__create_issue`），描述里带上插件名。冲突时加后缀。
- **工具清单**：拉一次 `tools/list` 存库，服务器通知 `tools/list_changed` 或管理员点「刷新」时更新。一个 run 内工具定义字节不变（提示缓存和思考块校验依赖它）。
- **上限**：单个插件最多给模型 40 个工具，一次对话启用的插件工具总数最多 80 个；超出时管理员在后台禁用一部分，或等第二期的工具搜索。
- **调用**：经 MCP 客户端调 `tools/call`，超时 60 秒，结果文字最多 2 万字（超出截断并说明，和 `web_fetch` 一样不一次返回整篇），图片按附件处理；`isError` 的结果照原样给模型。同一回复里的调用照常并发（`ToolConcurrency`）。
- **确认**：需确认的工具调用，run 停在调用处（`awaiting_input`），回复里画一张确认卡片：哪个插件、哪个工具、参数（格式化显示，长文本可展开）、「允许」「拒绝」，以及「本对话里这个工具都允许」。允许后服务端执行调用，结果作为这次调用的结果起续写 run；拒绝就把「用户拒绝了」作为结果。实现照 `ask_user` / `research_plan`（`agent.UserTool` + 回答接口）。
- **显示**：工具调用照常进活动行，图标用插件的图标，标题「GitHub · create_issue」。

## 7. 安全

- **地址**：插件只有管理员能加，地址可以是内网（2026-11-03 定）；连接时不过 `GuardedClient`，但 OAuth 发现过程中拿到的授权服务器地址（来自 MCP 服务的响应）仍然只允许 https 公网或与 MCP 地址同主机，防止被引到内网别的服务上。
- **提示词注入**：工具结果是外部数据，可能带「忽略之前的指示」之类的内容。系统提示词写明工具结果是数据不是指令；写操作的确认是最后一道防线，所以「需确认」是默认值。
- **数据外流**：模型写的参数会发到插件的服务。管理员添加插件时页面上写明这一点。
- **审核**：工具参数是模型写的、结果是外部数据，都不过内容审核（和联网一样）；用户在确认卡片上看得到参数。插件自带的技能是管理员写的，和站点技能一样不审。
- **审计**：每次调用记一行（谁、哪个插件、哪个工具、成功与否、耗时，不记参数和结果全文），后台可查。
- **权限变化即时生效**：管理员禁用工具或插件、用户断开连接，进行中的 run 下一次请求就拿不到这个工具（工具源每次请求都读）。

## 8. 工具太多怎么办（第二期）

1. **工具搜索**：模型先只看到每个插件一句话的说明和一个 `plugin_search` 工具，按需查出要用的工具，再把它们的完整定义加进下一次请求。代价是每加一批工具，提示缓存从那里断开。
2. **CodeMode**：插件工具不直接列给模型，模型写一段 JavaScript 在受限解释器里调用、组合结果，只交回最终值（OpenCode `packages/codemode`，思路来自 Cloudflare）。好处是多步操作一次完成、中间结果不进上下文；代价是要在 Go 里嵌一个 JS 解释器（如 goja，裁掉所有宿主能力），或者等沙箱。深度研究的研究员也能受益。

## 9. 和现有功能的关系

- **子 Agent**：默认拿不到插件工具；派出时可以点名只读工具（像点名技能一样），写工具永远不给子 Agent（没人能在子对话里点确认）。
- **深度研究**：研究员可以用点名的只读插件工具（比如查公司知识库），写工具不给。
- **定时任务**：任务以用户身份运行，可以用他已连接的插件；但没人在场点确认，所以任务里需确认的工具一律拒绝并说明，除非用户建任务时勾了「允许这个任务调用 X」。
- **临时对话**：可以用插件，不记「本对话都允许」之外的任何状态。
- **用量**：插件调用本身不花模型的钱，不进用量账本，只进审计日志；工具结果占的 token 照常算在对话里。

## 10. 以后再做

- **MCP Apps**：工具带一个 `ui://` 的 HTML 界面（MIME `text/html;profile=mcp-app`），在对话里用沙箱 iframe 画出来，通过 postMessage 走 JSON-RPC 调工具。Claude、ChatGPT、VS Code 都支持了（扩展规范 2026-01-26 稳定版）。我们已经有 GenUI 和 HTML 预览的 iframe 经验。
- **resources / prompts**：把资源当作可引用的附件，prompts 当作可选的快捷指令。
- **elicitation**：服务器在调用中途反问用户，接到 `ask_user` 的界面上。
- **插件目录**：内置一份常用插件（GitHub、Notion、Linear、Google Drive……）的地址、说明和配套技能，管理员一键添加。
- **导入导出**：插件打包成一个文件（MCP 配置 + 技能），在别的 OpenChat 上导入。

## 11. 技术选型

- MCP 客户端用官方 Go SDK `github.com/modelcontextprotocol/go-sdk`（v1.x，已支持 2026-07-28 版协议）。它的客户端 OAuth 还在实验阶段（要 build tag），所以 OAuth 流程自己写，用 `golang.org/x/oauth2` 做 PKCE 和刷新，SDK 只负责传输和协议。
- 新包 `internal/plugins`：插件、令牌、加密（`internal/secrets`，AES-GCM + 密钥版本）、OAuth、MCP 会话池（按「用户 × 插件」复用会话，空闲 5 分钟关掉）。
- 插件技能复用 `internal/skills` 的解析、版本和快照；工具像子 Agent 工具一样经 `ServerTools` 加进来（要查库、按用户取令牌）。
