# 插件（技能 + MCP）：方案

> 状态：第一期进行中。已做：插件目录与安装（`api/plugins.go`）；侧栏「插件」页；后台「插件」页（增删改、启停、图标、MCP 地址与认证方式、OAuth 应用、拉取工具、按工具三档权限，`api/plugins_admin.go`）；内置插件（GitHub）；`internal/secrets`（密钥自动生成在 `data/secret.key`）；`internal/plugins`（官方 Go SDK 列工具；OAuth 发现、动态注册、PKCE、换取与刷新令牌）；每人连接账号（`api/plugins_oauth.go`）。插件技能（`skills.plugin_id`，后台插件的「技能」页签）；子 Agent 与研究员点名插件（`conversations.plugins`，只给始终允许的工具）；定时任务的 run 无人值守（`runs.unattended`，需确认的调用立即拒绝）；工具返回的图片（`tool_images`，§6）；后台「插件调用」日志页；对话里调用插件工具（CodeMode，§6：`plugin_code`、`internal/codemode`、目录快照与轮次说明、直接列出开关、确认卡片、`plugin_calls` 审计）。还没做：Client ID Metadata Document；手机 App 的确认卡片（App 上触发的需确认调用照常等，10 分钟后按没回应处理）。

## 0. 结论先行

- **插件 = 技能 + MCP 连接。** 一个插件可以带一个远程 MCP 服务（模型能调用的工具）、若干技能（模型怎么用这些工具、怎么做这类事），或者两者都有。比如「GitHub 插件」：GitHub 的 MCP 工具，加上「怎么写 PR 描述」「怎么分诊 issue」两个技能。用户启用插件，就同时得到工具和用法。
- **管理员添加，用户自己挑选安装。** 管理员配一次 MCP 地址和认证方式，插件进入「插件」页；用户在侧栏「插件」页里挑选安装（2026-11-03 定），需要账号的服务（GitHub、Notion……）安装时用自己的账号授权（OAuth），模型只能以这个人的身份做事。装上的插件在他的对话里可用。
- **只接远程 MCP（Streamable HTTP）**，不在服务器上跑本地命令（stdio）。本地 MCP 等[沙箱](sandbox-plan.md)来了再说。
- **写操作默认要用户确认。** 工具没标 `readOnlyHint` 就当它会改东西，调用前停下来让用户点「允许」（脚本停在这次调用上等，§6）。管理员可以按工具设「始终允许 / 需确认 / 禁用」。
- **用户的第三方令牌加密存储**（新环境变量 `OPENCHAT_SECRET_KEY`，§5）。
- **管理员加的插件可以连内网**：自托管时接公司内部系统是主要用途。
- **插件工具走 CodeMode**（2026-11-03 定，照 OpenCode）：插件工具不逐个列给模型，模型只多一个 `plugin_code` 工具，在里面写一段 JavaScript 调 `tools.github.get_issue(...)`、组合结果，只交回最终值。系统提示词里放一份有预算的工具目录，目录外的用脚本里的 `search()` 查。所以接多少 MCP 都只多一个工具，多步操作一次跑完，中间结果不进上下文（§6、§8）。个别插件可以改成直接列出工具。

## 1. 别人怎么做

| 产品 | 做法 | 我们取什么 |
|---|---|---|
| ChatGPT（Apps / 开发者模式里的自定义 MCP） | 远程 MCP；写操作默认要确认，没标 `readOnlyHint` 的工具都当写操作；可以「记住这次批准」，换对话重新问 | 写操作确认、默认按写操作处理 |
| Claude（自定义连接器） | Team/Enterprise 由 Owner 添加，成员各自连接、各自启用；Owner 按工具设「始终允许 / 需确认 / 禁用」；Research 模式会自动调用工具，官方建议研究时关掉写工具 | 管理员加、用户各自授权；按工具的三档权限；深度研究只给只读工具 |
| Open WebUI（v0.6.31 起原生 MCP） | 只支持 Streamable HTTP（理由是多租户的 Web 架构）；只有管理员能加；OAuth 2.1 支持动态注册和预先注册的 client | 只接 Streamable HTTP；只有管理员能加；OAuth 两种注册方式 |
| Claude Code 插件 | 一个插件打包技能、MCP 服务器、命令、钩子，装上就都有了 | 「插件 = 技能 + MCP」的打包 |
| OpenCode CodeMode | 这是它接 MCP 的默认方式（服务配置 `codemode` 默认开）：工具不直接列给模型，只有一个 `execute`，模型写 JS 在自写的受限解释器里调工具、组合结果，只交回最终值；系统提示词里列出全部命名空间和约 2000 token 预算内的工具签名，其余用 `search()` 查；脚本里的每次调用照常过权限，需确认时脚本停在那次 `await` 上等用户；单个服务可设 `codemode: false` 改为直接列出 | 插件工具的调用方式整套照搬（§6），解释器换成 goja |

## 2. 插件由什么组成

后台「插件」页里，一个插件有：

- **基本信息**：名称、短名（脚本里的命名空间 `tools.<短名>`，`[a-z0-9-]`，带连字符时模型写 `tools["my-crm"]`）、图标、一句话说明（给用户看，也给模型看）。
- **MCP 连接**（可选）：地址、认证方式（§5）、工具清单（拉取后逐个设权限）。
- **技能**（可选）：插件自带的技能，格式和站点技能一样（`SKILL.md`），在后台插件的「技能」页签编辑（`/admin/plugins/{id}/skills`），存在 `skills` 表里、`plugin_id` 指向插件（不是站点的，也不是哪个人的）。只有装了这个插件、插件开着且本人看得到时，才进他的新对话的技能快照；管理员写的，不审。同名时个人的盖过站点的、站点的盖过插件的、插件的盖过内置的。版本照技能的规则保存，但后台还没有回退版本、导入导出的入口。
- **谁能用**：所有人 / 只有管理员（以后接用户组）。
- **开关**：停用后所有对话都拿不到它的工具和技能，用户的授权保留。

只有技能、没有 MCP 的插件也成立（相当于一组打包的站点技能，但能按对话开关）；只有 MCP、没有技能的也成立。

站点技能（后台「技能」页）和插件的技能是两回事：前者对所有对话可见，后者跟着插件开关。以后可以考虑把站点技能都收进插件，第一期不动。

### 2.1 内置插件与图标（2026-11-03）

- **内置插件**定义在 `internal/plugins/builtin.go`，每次启动时补上库里还没有的（`plugins.builtin` 记定义的键），**默认关闭**：要等管理员把自己那部分配好（比如 GitHub 的 OAuth App）再打开。管理员可以改、可以关，不能删（409 `plugin_builtin`）；短名已被管理员自己的插件占用时跳过。
- 第一个内置插件是 **GitHub**：官方托管的 MCP 服务 `https://api.githubcopilot.com/mcp/`，每人用自己的账号授权。实测它的受保护资源元数据指向 `https://github.com/login/oauth`，GitHub 不支持动态注册客户端，所以管理员要先在 GitHub 上注册一个 OAuth App（回调地址指向本站），等账号授权做好后在后台填 client ID 和 secret。
- 第二个内置插件是 **arXiv**（2026-11-03）：arXiv 没有官方 MCP 服务，就在 OpenChat 进程里跑一个（`internal/plugins/arxiv`）。地址写成 `openchat:arxiv`（`plugins.LocalScheme`），连接时不走网络，用 SDK 的内存传输（`plugins/local.go`）；后台列表的「服务」显示「OpenChat 内置」。三个只读工具：`search_papers`（关键词或 arXiv 检索语法，可按分类、日期过滤，按相关度/提交/更新排序）、`get_paper`（完整元数据）、`read_paper`（全文，先读 arXiv 生成的 HTML，没有就读 PDF，按段续读，最近读过的缓存 30 分钟）。不需要账号，管理员打开、拉取工具即可。按 arXiv 的使用条款，进程内所有对 arXiv 的请求排队，每 3 秒至多一个。arXiv 的检索很朴素：普通词逐个必须出现、常用词不入索引，所以去掉常用词、保留引号里的短语，工具说明让模型优先用引号短语或 `ti:`。
- **内置插件带技能**（2026-11-03）：GitHub 的 `github-work`、arXiv 的 `arxiv-research`，文件在 `internal/plugins/builtin_skills/<键>/<技能>/`，随二进制发布，启动时写进插件的技能（`EnsureBuiltinSkills`，`app_settings.builtin_plugin_skills` 记每个技能上次发布的哈希：没写过的补上；内容仍是上次发布那版的更新到新版；管理员改过的、删掉的都不动）。插件的技能只在插件有未禁用的工具时进快照：实测一个启用了却没拉取工具的 arXiv，模型读了技能找不到工具，转去网页搜索。
- **工具自动拉取**（2026-11-03）：添加插件、改了地址或认证时自动拉一次；要账号的插件在管理员第一次连上自己的账号时拉；进程内的内置插件每次启动时拉。拉不到不影响保存。
- **又一批进程内的内置插件**（2026-11-03）：OpenAlex（论文的引用、参考文献、学者，`plugins/openalex`；按每日额度计费，不填 key 时同一 IP 的人共用很小的免费额度，所以插件的认证方式是「请求头」，管理员把 key 填成值，服务当 `api_key` 发）、天气（Open-Meteo，`plugins/weather`；按名字查地点时按名字的文字选语言，地理编码只匹配所问语言的名字；Open-Meteo 对非商业用途免费）、维基百科（`plugins/wikipedia`；`zh` 转简体，`zh-tw`/`zh-hk` 繁体，给出条目在其他语言的标题）、Hacker News（`plugins/hackernews`，Algolia 的接口；讨论按楼层顺序给，最多 2 万字）。各带一个技能。共用 `plugins/localkit`。
- linux.do（2026-11-03 评估，不做）：它全站对非浏览器客户端开 Cloudflare 验证，现成的 linuxdo-mcp 靠用户本机 Chrome 的 `cf_clearance` 过盾；放到服务器上只能让无界面浏览器伪装成真人去过盾，这等于绕过站点的机器人检测，不做。管理员可以自己部署后当普通远程插件接入。
- **图标**用 Simple Icons（simpleicons.org，CC0，npm `simple-icons`）。后台表单里按名字搜索挑选，图标库约 5 MB，只在打开挑选框时按需加载；选中后把 slug、SVG 路径和品牌色存进插件（`icon_slug`、`icon_path`、`icon_color`），用户的插件页直接画存下的路径，不加载图标库。路径只允许 SVG 路径命令和数字（服务端校验）。图标画在品牌色的方块上，浅色品牌用深色图形（`lib/plugin-icon.ts`）。没有图标时显示标志文字。内置插件的图标在后来的版本里补上时，只填给还没有图标的行，不覆盖管理员选的。

## 3. 范围

第一期：

- 传输：Streamable HTTP（MCP 规范 2025-06-18 起的标准远程传输）。老的 HTTP+SSE 传输不做。
- MCP 能力：只用 **tools**（`tools/list`、`tools/call`）。resources、prompts、elicitation（服务器反问用户）、sampling（服务器借用模型）、MCP Apps（工具带交互界面）放到后面（§10）。
- 认证：无认证、固定请求头、每人 OAuth（§5）。

不做：用户自己添加插件、stdio 本地服务器、把 OpenChat 自己暴露成 MCP 服务器（另一件事）。

## 4. 管理员和用户各做什么

- **管理员**（后台 → 插件）：增删改插件；拉工具清单，逐个工具设权限（默认按 `readOnlyHint` 给：只读的始终允许，其余需确认）；看调用日志。
- **用户**（侧栏「插件」页，在「定时任务」下面）：浏览管理员添加的、自己能用的插件，搜索、按「全部 / 已安装」筛选；点「安装」，需要账号的接着走 OAuth 授权，授权完成才算装上；已安装的可以看详情（连接状态、工具和各自的权限、自带的技能）、断开账号、卸载。卸载删掉他的令牌和安装记录。页面样式见效果图（三版待选）。
- **没连接时**：插件在对话里显示「未连接」，模型调用时返回「用户还没连接 X，请提醒他去设置 → 插件里连接」，不在对话中途弹登录（Open WebUI 的坑：后台没法替用户发起浏览器登录）。模型据此提醒用户，活动行里的这次调用旁边给「去连接」的入口。

## 5. 认证与令牌

- **无认证**：内部服务或公开服务。
- **固定请求头**：管理员填 `Authorization: Bearer …` 之类，所有人共用一个身份。适合只读的公共数据源；写操作要慎用，因为所有人都以同一个身份写。管理员填的这个值也加密存储。
- **每人 OAuth**：按 MCP 授权规范走 OAuth 2.1 + PKCE：
  - 先请求 MCP 地址拿 401，读 `WWW-Authenticate` 里的受保护资源元数据（RFC 9728）找到授权服务器，再读授权服务器元数据；
  - 客户端注册优先用 **Client ID Metadata Document**（我们在 `https://<站点>/oauth/client.json` 放一份客户端元数据，用这个网址当 client_id，2025-11 版规范起的首选）；不支持就退到**动态注册**（RFC 7591）；都不支持就让管理员填预先注册的 client_id/secret；
  - 回调地址 `https://<站点>/api/plugins/oauth/callback`，`state` 一次性、绑定用户和插件，带 `resource` 参数（RFC 8707）；
  - 存 access token、refresh token、过期时间；过期前自动刷新，刷新失败标记为「需重新连接」。

**已实现的连接流程**（2026-11-03，`api/plugins_oauth.go`、`internal/plugins/oauth.go`）：

- 插件页点「去 XX 授权」→ `POST /plugins/{id}/connect`：先发现授权服务器（请求 MCP 地址拿 401 里的 `resource_metadata`，再试 `/.well-known/oauth-protected-resource{path}`；授权服务器元数据按 RFC 8414 的插入路径、再按 OpenID 的两种位置找）。服务返回的地址只在 https 或与 MCP 地址同主机时才跟；授权服务器声明了 PKCE 方法却没有 S256 就拒绝。
- 客户端：管理员填的 Client ID/Secret（Secret 加密保存），没填且服务器有 `registration_endpoint` 就当场动态注册并存下来（`oauth_registered`），都没有就 409 `plugin_oauth_unconfigured`。GitHub 不支持动态注册，必须在 GitHub 上注册 OAuth App，回调地址填后台显示的 `<站点>/api/v1/plugins/oauth/callback`。还没做 Client ID Metadata Document（要有固定的公网地址）。
- 授权地址带 PKCE（S256）、`state`、`resource`（RFC 8707）和管理员设的 scope；`state` 只存 SHA-256，PKCE verifier 加密保存，10 分钟有效、只能用一次、只能由发起的那个人取（`plugin_oauth_states`，清扫循环删过期的）。
- 回调 `GET /plugins/oauth/callback`：取走 state，有 `iss` 时核对是不是同一个授权服务器（RFC 9207），换取令牌，加密存进这个人的安装记录（`plugin_installs.access_token`/`refresh_token`/`token_expires_at`），装上插件，跳回 `/plugins?connected=<短名>`；失败跳回 `?connect_error=<原因代码>`，页面按代码显示，不回显服务器的原话。
- 令牌快过期时用 refresh token 换新的；刷新被拒就标记 `needs_reconnect`，插件页提示重新连接。同一人同一插件的刷新在进程内排队（`takePluginRefresh`），拿到号后重读安装记录，别人刚换过就直接用新的：会轮换 refresh token 的服务拒绝用过的旧令牌，并发的工具调用各自刷新会把好好的连接标成失效。标记只在被拒的 refresh token 仍是库里那份时生效（`MarkPluginNeedsReconnect` 带上它），网络失败不标。
- 发现、注册、换令牌、刷新的请求都走 `plugins.httpClient`：管理员填的服务地址那个 host:port 照原样连（可以是内网），其余地址是别的服务器说的，每次拨号都只连公网地址（同 `GuardedClient`），每一跳重定向也要满足「https，或服务自己的主机」，不读环境代理。
- 后台「拉取工具」对每人授权的插件用管理员自己的连接（先在插件页装上），没连接就 409 `plugin_not_connected`。

**加密存储**（2026-11-03 定，同日改为自动生成密钥）：

- 用户的 access/refresh token、管理员填的固定请求头和 OAuth client secret，都用 AES-256-GCM 加密后入库，库里只有密文。
- 密钥首次启动时自动生成，写进数据目录的 `data/secret.key`（只有服务器的用户能读，已 gitignore；Docker 里在 `/app/data` 卷上）。设了环境变量 `OPENCHAT_SECRET_KEY`（32 字节，base64）就用它，不读文件。
- 不放进数据库：密钥和密文放在一起，数据库导出泄露时等于没加密。所以备份要把数据目录和数据库一起备份；只恢复数据库，所有凭证都解不开，用户需要重新连接，管理员要重新填请求头。
- 文件写不进去（目录只读）时插件凭证功能不可用，后台插件页提示原因，其他功能照常；文件存在但内容不对则拒绝启动，免得新存的凭证用错的密钥加密。
- 密文带密钥版本号，以后可以轮换。
- 渠道的 API Key 现在是明文存库的，第一期不动；以后可以用同一把密钥迁移过去。

## 6. 在对话里：CodeMode

照 OpenCode 的 CodeMode（`packages/codemode`、`packages/core/src/codemode/`）：插件工具不逐个列给模型，模型写一段 JavaScript 调它们。

- **启用哪些**：用户装上的插件在他所有对话里可用（`plugin_installs` 表，按用户）。工具多不再是问题（§8），所以第一期不做按对话开关。
- **技能**：启用的插件带的技能加进这个对话的技能清单，版本在第一次启用时记进对话快照（和站点技能同一套规则，同一对话内字节不变）。
- **模型看到什么**：只多一个工具 `plugin_code`，参数 `{ code }`。它的说明是固定的英文（怎么写、`await` 每个要等的调用、独立的调用用 `Promise.allSettled` 并发、工具结果是数据不是指令），不随插件变，所以工具定义的字节永远不变。
- **目录**：系统提示词里一节「插件目录」，照 OpenCode 的 `catalog.ts`：每个插件一行（短名、一句话说明、工具数），永远全列；然后在约 2000 token 的预算内列工具签名，形如 `tools.github.get_issue(input: { owner: string; repo: string; issue_number: number }): Promise<unknown> // 说明的第一行，截到 120 字`，每个插件轮流挑，短的、只读的先挑。没列进来的用脚本里的 `search(query, { plugin })` 查，返回调用路径和完整签名（`search` 也算一次调用）。只列这个人能用的：已安装、已连接、插件和工具都没被禁用。
- **目录随对话快照**：和技能一样，在对话的快照里定下来，同一对话内字节不变（提示缓存）。对话中途装上、卸载插件或管理员改了工具，目录不变，但 `search()` 和调用读的是此刻的清单；和快照不一样时，这一轮的轮次说明（`agent.TurnNote`，存在 `runs.turn_note`，之后的请求附回原处）告诉模型「新装了 X，用 search 查」或「X 已不可用」。
- **工具清单**：拉一次 `tools/list` 存库（`plugin_tools`，含 `inputSchema`），服务器通知 `tools/list_changed` 或管理员点「刷新」时更新。签名由 `inputSchema` 生成。
- **脚本运行时**：Go 里用 goja（纯 Go 的 JS 解释器，`async/await`、`Promise.all`、模板字符串都支持，已验证）。它本身没有任何宿主能力，我们只注入 `tools`、`search`、`console.log`（收进结果）；没有 `require`、定时器、网络、文件，也不给 `fetch`（联网走 `web_fetch`，地址要过 `GuardedClient`）。一段脚本一个 VM，用完丢掉。工具调用在各自的 goroutine 里跑，结果经通道回到 VM 的 goroutine 再 resolve（VM 不是并发安全的）。
- **上限**（都可在后台改）：一段脚本的活动时间 120 秒（等用户确认的时间不算），超时用 `vm.Interrupt` 打断、进行中的调用随 ctx 取消；工具调用最多 50 次，同时进行最多 8 个；单次调用超时 60 秒；返回值加日志最多 2 万字，超出截断并说明（和 `web_fetch` 一样不一次返回整篇）；数据嵌套最多 32 层。点「停止」时脚本和进行中的调用一起取消。OpenCode 聊天里的 `execute` 不设时长、次数、并发上限（只有 32 层嵌套、每个 MCP 请求自己的超时，默认 5 秒，以及所有工具通用的 2000 行 / 50 KB 输出截断；它的定时任务检查脚本才设 30 秒、20 次、32 KB）：它是一个人在自己电脑上用，跑飞了按 Ctrl-C。我们是多人共用的服务器，死循环占的是大家的 CPU，无限次调用是拿用户的令牌连续请求第三方服务，所以要设。
- **一次调用**：`tools.<短名>.<工具名>(参数)` 返回 Promise。服务端依次：按 `inputSchema` 校验参数（不合格就在脚本里抛错，说明哪里不对）→ 查权限（禁用的、子 Agent 拿不到的直接抛错）→ 取这个人的令牌（快过期就刷新，没连接就抛「用户还没连接 X」）→ 需确认的等确认 → 经 MCP `tools/call`。结果有 `structuredContent` 就用它，否则把文字内容拼起来（是 JSON 就解析）；`isError` 在脚本里抛错，带服务的原话；图片等非文字内容第一期丢掉并在结果里说明。
- **`plugin_code` 的结果**：脚本的返回值（JSON）、日志、每次调用的摘要（工具、成功与否）。出错时给带行号的诊断：语法错、不支持的语法、不认识的工具、参数不合格、超出上限、脚本抛出的错误，模型照着改了再跑。同一回复里的 `plugin_code` 和别的工具照常并发（`ToolConcurrency`）。
- **直接列出（兜底）**：后台每个插件有「直接列出工具」开关，默认关，照 OpenCode 的 `codemode: false`。开了的插件不进目录，它的工具按 `<短名>__<工具名>`（如 `github__create_issue`）直接给模型，一次调一个；给写不好脚本的模型，或本身就是 CodeMode 的服务（免得套两层）。权限、确认、审计和脚本里的调用同一套。直接列出的工具单个插件最多 40 个。
- **确认**：需确认的调用，**脚本停在这次调用的 `await` 上，run 不结束**（和 OpenCode 一样）。不照 `ask_user` 那样结束 run 再接着跑，因为接着跑就得重放整段脚本，而前面的调用可能已经改过东西。
  - 服务端写一行待确认（`plugin_confirmations`：run、对话、调用序号、插件、工具、参数、状态），随 live 状态下发，回复里画确认卡片：哪个插件、哪个工具、参数（格式化显示，长文本可展开）、「允许」「拒绝」「本对话里这个工具都允许」。刷新页面、换设备，卡片从快照里来。
  - 用户回答走 `POST /conversations/{id}/plugin-confirmations/{confirmationId}`：只认本人、本对话、还在等的；写下状态后通知等待的调用（`Runner` 里按确认 id 等的通道）。允许就执行；拒绝就在脚本里抛「用户拒绝了这次调用」，模型据此换做法或问用户。
  - 等待时 run 仍是 `running`，照常占并发名额；输入框是「停止」，点停止就当拒绝并结束 run。最多等 10 分钟，过时按「用户没有回应」拒绝。
  - 一段脚本里可以同时有几个调用在等（`Promise.all`），卡片按调用序号排。
  - 「本对话都允许」记在 `plugin_tool_grants`（对话 × 插件 × 工具），之后这个对话里直接执行；管理员把工具改成禁用时照样禁用。
  - 服务器在等待中重启：和其他进行中的 run 一样以失败结束，待确认的行作废，用户重新问就好。
- **直接列出的工具的确认**：同一套，只是停在那次工具调用上，不在脚本里。
- **图片**：调用返回的图片（MCP `image` 内容）按字节认类型，只收 PNG、JPEG、GIF、WebP，一次 `plugin_code`（或一次直接调用）最多 4 张、每张 4 MB，存进 `tool_images`（随 run 级联删除），结果里记引用（`ToolResultPart.Images`）。页面在步骤下显示缩略图（`GET /conversations/{id}/tool-images/{imageId}`，只给本人）；构建上下文时这一轮的结果之后跟一条带图片的消息交给模型（多数服务商只在用户消息里收图片），模型不收图片就换成一行说明。音频、资源等其他内容仍然丢掉并说明。
- **显示**：`plugin_code` 进活动行，图标用插件的图标，标题写涉及的插件和调用次数（「GitHub · 3 次调用」），展开是每次调用（工具、参数摘要、成功与否），代码折叠在最里面。

## 7. 安全

- **地址**：插件只有管理员能加，地址可以是内网（2026-11-03 定）；连接时不过 `GuardedClient`，但 OAuth 发现过程中拿到的授权服务器地址（来自 MCP 服务的响应）仍然只允许 https 公网或与 MCP 地址同主机，防止被引到内网别的服务上。
- **提示词注入**：工具结果是外部数据，可能带「忽略之前的指示」之类的内容。系统提示词写明工具结果是数据不是指令；写操作的确认是最后一道防线，所以「需确认」是默认值。
- **数据外流**：模型写的参数会发到插件的服务。管理员添加插件时页面上写明这一点。
- **审核**：工具参数是模型写的、结果是外部数据，都不过内容审核（和联网一样）；用户在确认卡片上看得到参数。插件自带的技能是管理员写的，和站点技能一样不审。
- **审计**：脚本里的每次工具调用都记一行（谁、哪个对话、哪个插件、哪个工具、成功与否、是否经过确认、耗时，不记参数和结果全文，也不记脚本），后台可查。
- **权限变化即时生效**：管理员禁用工具或插件、用户断开连接，进行中的脚本下一次调用就被拒（权限和令牌每次调用都现查，不看对话快照里的目录）。
- **脚本本身**：模型写的代码只在 goja 里跑，碰不到服务器的任何东西，只能经我们注入的 `tools`、`search` 出去，每一次都过上面的检查；死循环靠活动时间上限打断，内存靠调用次数、输出大小和嵌套层数的上限压住。

## 8. 工具多了怎么办

CodeMode 本身就是答案：工具定义只有 `plugin_code` 一个，目录有 2000 token 的预算，其余靠 `search()`，所以没有「总共最多多少个工具」的上限。只有改成直接列出的插件还受单个插件 40 个工具的限制。

以后可以考虑：

- 目录的预算按模型的上下文窗口调。
- 插件多到连「每个插件一行」都放不下时（OpenCode 也还没解决），只列安装最久、最常用的，其余靠 `search()`。
- 沙箱来了以后，脚本可以搬进沙箱跑，支持完整的 JS 和包；那时再考虑给脚本 `fetch`。

## 9. 和现有功能的关系

- **子 Agent**：默认没有 `plugin_code`；派出时用 `plugins` 参数点名插件（像点名技能一样，记在子对话的 `conversations.plugins`，只能点名有「始终允许」工具的已装插件），它的目录和 `search()` 只有点名插件里「始终允许」的工具，别的工具在脚本里不存在，调用时也再查一次权限。
- **深度研究**：研究员同上，可以用点名插件里始终允许的工具（比如查公司知识库）。CodeMode 对研究员尤其有用：一段脚本查十几次，只把整理好的结果交回。
- **定时任务**：任务以用户身份运行，可以用他已连接的插件；调度器起的 run 记为无人值守（`runs.unattended`，「立即运行」不算），需确认的调用不等，直接按拒绝抛错并说明。以后可以加「允许这个任务调用 X」。
- **临时对话**：可以用插件，不记「本对话都允许」之外的任何状态。
- **用量**：插件调用本身不花模型的钱，不进用量账本，只进审计日志；工具结果占的 token 照常算在对话里。

## 10. 以后再做

- **MCP Apps**：工具带一个 `ui://` 的 HTML 界面（MIME `text/html;profile=mcp-app`），在对话里用沙箱 iframe 画出来，通过 postMessage 走 JSON-RPC 调工具。Claude、ChatGPT、VS Code 都支持了（扩展规范 2026-01-26 稳定版）。我们已经有 GenUI 和 HTML 预览的 iframe 经验。
- **resources / prompts**：把资源当作可引用的附件，prompts 当作可选的快捷指令。
- **elicitation**：服务器在调用中途反问用户，接到 `ask_user` 的界面上。
- **插件目录**：内置一份常用插件（GitHub、Notion、Linear、Google Drive……）的地址、说明和配套技能，管理员一键添加。
- **导入导出**：插件打包成一个文件（MCP 配置 + 技能），在别的 OpenChat 上导入。

## 11. 技术选型

- MCP 客户端用官方 Go SDK `github.com/modelcontextprotocol/go-sdk`（v1.x，已支持 2026-07-28 版协议）。它的客户端 OAuth 还在实验阶段（要 build tag），所以 OAuth 流程自己写，用 `golang.org/x/oauth2` 做 PKCE 和刷新，SDK 只负责传输和协议。
- 新包 `internal/plugins`：插件、令牌、加密（`internal/secrets`，AES-GCM + 密钥版本）、OAuth、MCP 会话池（按「用户 × 插件」复用会话，空闲 5 分钟关掉）。
- 插件技能复用 `internal/skills` 的解析、版本和快照；`plugin_code`（和直接列出的工具）像子 Agent 工具一样经 `ServerTools` 加进来（要查库、按用户取令牌）。
- 脚本解释器用 `github.com/dop251/goja`（纯 Go，不需要 cgo；ES6 大部分和 `async/await`）。OpenCode 自己写了一个只支持部分语法的解释器，好处是「只有实现了的才能跑」；goja 默认同样没有任何宿主能力，我们不注入就碰不到，所以不自己写。2026-11-03 实测：宿主返回的 Promise 在另一个 goroutine 里完成、经通道回到 VM 再 resolve，`await Promise.all([...])` 正常；`Interrupt` 能打断死循环；`require`、`setTimeout`、`fetch`、`process` 都不存在。

## 13. 已定与待定

已定（2026-11-03）：

1. 页面上叫「插件」，插件 = 技能 + MCP。
2. 用户不能自己添加插件，只能连接管理员加的。
3. 用户的第三方令牌加密存储；密钥自动生成在 `data/secret.key`，不放进数据库。
4. 管理员加的插件可以连内网。
5. 侧栏「定时任务」下面加「插件」入口，用户在插件页里挑选安装。
6. 插件工具走 CodeMode（照 OpenCode）：模型写 JS 调工具，需确认的调用让脚本停下等；每个插件可以改为直接列出工具。

待定：

7. **写操作确认的默认值**（实测：DeepWiki 的 MCP 服务三个工具都只是读，却都没标 `readOnlyHint`，按现在的规则全是「需确认」，管理员要手动改成始终允许。后台把这种工具标为「未标为只读」而不是「可能删改」）：没标 `readOnlyHint` 的工具一律需确认（ChatGPT 的做法），还是相信服务器的标注、只有标了 `destructiveHint` 的才确认？方案按前者写。
8. **等确认的 run 占不占并发名额**：方案按「占」写（它确实还在跑，脚本和 VM 都在内存里）。如果用户常常同时开几个对话等确认，再考虑等待期间不算。
9. **小模型写脚本的能力**：DeepSeek Flash 这类模型写 JS 调工具靠不靠得住，做出来后用 Haiku 和 DeepSeek 实测；不行的话加一个按模型的开关（这个模型的插件一律直接列出），而不是按插件。
